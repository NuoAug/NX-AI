### 为什么会看到 5.4 GB

目前可以确认的因素与边界：

1. 当前模型服务加载 Qwen3.5-2B Q4_K_M、F16 视觉投影，使用上下文 4096、GPU 层数 99、单槽位。模型权重之外还存在上下文、视觉处理及运行缓冲；文件体积不能直接当成进程内存。
2. 当前启动参数是 `batch=2048 / ubatch=512`；阶段 7 的采用值是 `256 / 128`，运行参数与已记录基线不一致。
3. 但阶段 7 的旧对比只显示约 **0.14 GiB** 收益（整栈 4.05 → 3.906 GiB）。因此不能把现在的全部增量归因于批大小，也不能承诺改回参数就必定达标。
4. 正式 VLM 图像编码路径会按配置把长边限制到 1024。不能因为上传原图宽度是 4096，就断言模型直接处理原尺寸导致高内存。
5. 本次采样时没有离线测试进程或测试台工作进程在运行，测试台 HTTP 服务约 36 MiB。当前大头不是 HTTP 页面服务。
6. 两次空闲采样没有继续增长，但无法重建此前每次请求的分配过程。请求后保留缓冲、驱动/映射统计差异、实际泄漏均未完成归因；目前只列为待查，不写成已确认根因。

换算按 1 GiB = 1,048,576 kB。系统监视器的截图是此前时刻，不能与本次采样当作同一瞬时值比较。原有预算是整栈预算，不能改为只统计 Python 或只取 PSS 而不说明口径。

## 三、待批准的最小整改方案

### 1. 先统一内存测量，再决定优化

**依赖：批准短时独占模型测试窗口。** 模型是共享服务，重启前核对没有队友正在调用。不得直接杀进程抢占。

实施顺序：

1. 固定模型文件、llama.cpp 版本、启动参数及同一批输入，记录现状；固定冷启动、文本问答、单图、双图、停止及再次问答的顺序。录音采用用户提供的文件，不打开真实麦克风。
2. 先对当前 2048/512 参数取得完整采样，再仅通过现有脚本的环境变量切换为 `LLAMA_BATCH=256 LLAMA_UBATCH=128`。保持上下文、模型、GPU 层数和输入不变；不修改正式启动脚本。
3. 两组均记录模型和工作进程的 VmRSS/VmHWM、各自 smaps RSS/PSS、测试台自身占用、系统 MemAvailable 和可取得的 Jetson 内存数据。标清采样时刻、当前值与进程生命周期高水位，保留原始数据。
4. 对共享映射和统一内存分别说明，不把 GPU 和 CPU 统计不加区分地相加。先报告既有 RSS 口径下的保守整栈结果，同时呈现其他口径供核对，不悄悄更改 4 GiB 标准。
5. 只有数据提示累积增长时，才补一个固定输入的短重复测试；无新疑点不做压力测试。确认是哪一阶段增加，区分首次分配后稳定与持续增长。
6. 若恢复参数仍不能满足预算，列出分配来源和实测差额，再提交下一步取舍；不自行缩短上下文、降低图片清晰度、更换模型或升级依赖。

**验收：** 提供两组可比结果和峰值来源。只有整栈口径明确且实测不超过既有 4 GiB，才报告内存项通过；否则明确失败，不能以较低的 PSS 替代承诺。

### 2. 修正测试台退出后的工作进程状态

只修改 `testbench/` 内服务状态同步：工作进程退出/回收时同步清除派生存活状态；工作进程尚未创建时，显示未启动，不冒充异常或就绪。前端显示与实际进程状态一致。

**验收：** 依次覆盖未启动、启动、任务完成回收、再次启动四个状态；API 状态、PID 和页面一致。补一项对应退出回收的回归检查，不重构整体状态体系。

### 3. 视觉先修最明确的误检，不以调用成功交付

先为已见错例标注人工参考答案，保留无目标负样本与有目标正样本，所有数据放在 `testbench/`。分开统计 OCR、描述、找物，不用一个总成功率掩盖误检。

首选实验是在测试台专用适配路径中，对找物候选增加局部图像复核，并核对结构化结果和实际可见内容；对不确定候选输出不确定结果。该方法可能增加一次模型调用，必须同时测时延和内存，验证有效后才保留。不能只按颜色硬编码排除，也不能为通过负样本而一律回答没有。

OCR 先定位错误来自取图区域还是识别输出，再用已有裁剪/识别能力做最小对比。不得为修一张图添加固定答案。若需要正式项目代码修改、替换模型或引入新依赖，另列具体差异审批，不在这一步直接改。

**验收：** 篮球场负样本不再误报灭火器，真实灭火器正样本仍能检出；共享充电宝柜不再作为确定的售货机回答；文字错例重新逐条核对。用另选的未用于调整的图片做简短复验，同时报告新增耗时和仍错误的内容。达不到则保留问题，不宣称完成。

### 4. 录音识别按已知错例做针对性排查

为九段录音整理逐字参考文本；保留独立 ASR 与完整交互两条测试路径的区别。先检查采样率、输入归一化、端点及尾段是否完整送入。此前补 0.66 秒尾部静音的对比没有改善，不重复采用无效方案。

只有证据表明输入或端点存在问题，才修改测试台相应路径；若属于模型识别能力，保留错误率报告并另提取舍，不擅自换模型、注册声纹或修改正式项目参数。

**验收：** 两个已知错例前后逐字对照，其他七段无新退化；三人各一次完整回放仍完成，停止后能继续。不用硬件播放效果替代 ASR 判定。

### 5. 最后做一次核心流程交付检查

沿用已有测试；完成修改相关的针对性检查后，只做一轮文本、上传单图/双图、文件音频交互、停止再启动、Intel 预览释放、设备菜单与占用提示的核心回归。

保持现有页面布局，选中设备名固定单行省略，展开才显示完整名称。默认使用系统默认外接设备；设备列表不锁定单一相机。打开设备前检查可见占用，遇到占用拒绝并提示应用/PID；权限不足时显示无法核实，不保证其他软件一定遵守独占。

蓝牙设备在线且用户方便时再安排一次现场收音/播音验收；未完成时单独标记，不用模拟结果代替。所有物理采集只在确认空闲的授权设备上执行。
