## 4. 固定实现结构

采用 Python 标准库 HTTP 服务 + 原生 HTML/CSS/JS，不增加前端构建链，不引入新 Web 框架。测试台一个 HTTP 服务进程管理一个按需创建的业务工作进程，防止阻塞推理卡住停止按钮和健康接口。

```text
/home/mylin/Desktop/Nuo/testbench/
  index.html               已确认页面；样式保留
  app.js                   从页面拆出的真实前端逻辑
  server.py                HTTP 路由、状态快照、静态文件、上传
  supervisor.py            单工作进程、任务互斥、停止与进程归属
  worker.py                命令处理、业务实例生命周期
  bridge.py                原业务观测包装与事件转换
  media.py                 共享相机、实际取帧、上传图片管理
  metrics.py               /proc、温度和GPU可用指标
  debug.py                 本文列出的固定模块调试入口
  config/bench.json        测试台配置
  scripts/start.sh         仅启动HTTP服务
  scripts/stop.sh          停止测试台自有进程
  tests/                   必要软件检查
  runs/<run_id>/           config.json、events.jsonl、metrics.jsonl、result.json、media/
  uploads/                 当前A/B图片，内部随机ID命名
  logs/                    HTTP/工作进程日志
  .runtime/                PID、锁、IPC文件、缓存、临时数据
  README.md                操作、访问、停止与移除说明
  执行方案.md              本文件
```

这些是职责划分，不额外建设插件系统、数据库、账户系统或任务调度框架。模块只实现本文所需接口。

配置固定初值：监听 `127.0.0.1:18780`；项目根 `/home/mylin/Desktop/Nuo`；正式配置引用 `config/target.json`；模型地址沿用正式配置；设备输入/输出覆盖为 null；前端状态轮询 500 ms；资源采样 2 s；预览最高 5 fps；上传单文件 20 MiB，像素总数不超过 2400 万。

运行器固定使用项目 `.venv/bin/python`，设置 `PYTHONPATH=<项目根>/src`。`PYTHONDONTWRITEBYTECODE=1`，临时目录、XDG 缓存、CUDA 缓存和 pytest 缓存均定向到测试台目录；不修改用户全局环境。已有模型/运行器/项目依赖只引用，不复制、不安装升级。

HTTP 使用 `ThreadingHTTPServer`，绑定回环。前端与接口同源，禁止通配 CORS。POST/DELETE 校验同源 Origin（缺失时只允许带服务启动时生成会话令牌的请求），拒绝跨站设备控制；令牌存在内存，页面启动时同源读取，不写日志。静态路由使用白名单，不把整个项目目录作为静态目录。JSON/上传请求设置体积上限和读超时。

HTTP与工作进程通过专用管道传递按行JSON命令/事件；stdout专供协议，业务输出写stderr到测试台日志。单条事件不传原始音频/大图片，图片传内部ID和元数据。记录 `run_id`、单调递增 `seq`、`request_id`；停止后的旧运行事件不得覆盖新运行状态。

工作进程由首次预览或测试请求按需创建；已有预览worker可接收综合测试/调试命令，不再创建第二个占用相机的worker。一个worker同时最多一个业务任务，预览是独立引用。综合测试停止默认同时关闭该轮预览并回收worker；仅点“停止预览”则只释放预览引用。任务结束后用户再次开启预览或开始测试才创建下一实例。

## 6. 实施步骤 2：后端生命周期与隔离

1. 先实现HTTP健康、静态页面、真实只读状态，不加载模型、不开音频、不打开摄像头。
2. 实现 `Supervisor`：同一时刻仅一个综合或调试任务，任务创建受锁保护；重复开始返回409，不再开实例。预览可与综合测试共享同一个工作进程的相机。
3. 创建工作进程时保留PID、Linux进程启动时间和进程组，全部记录在 `.runtime/`。停止前核对三项归属，不能只信PID文件，不能使用 `pkill -f` 清理。
4. worker 使用 `build_engine` 注入真实观测包装器和共享相机提供者。业务初始化、启动和关闭遵循 `app.run_app`；HTTP线程不直接操作音频或状态机。
5. 启动顺序：生成本轮配置副本 → 检查现有模型健康 → 装配组件 → sink.start → engine.start → 合同启用时 contract.start → frontend.start → 发布 running。
6. 配置副本重定向 evidence/log/enroll等可能写入路径到本目录，输入/输出device设null；模型路径保留正式目录。记录实际配置，不改正式JSON。
7. 停止顺序：标记 stopping 并拒绝新任务 → 停止本轮采集和预览 → 停止合同/engine → 关闭frontend、sink、TTS、scene、注入provider和身份资源 → 写result → 退出worker。每一项放在独立finally，前项报错也要继续释放。
8. worker 10秒未退出，向已核实的自有进程组发SIGTERM，再等3秒，仍未退出才SIGKILL，记录 interrupted；不得显示正常完成。只终止自有worker，不触碰已有llama-server。
9. 已有llama-server只做健康检查和调用，不重启、不改参数。未运行时显示 model_unavailable 并禁用依赖它的测试；给出项目原有启动入口供用户单独启动，不在测试台后台静默启动。
10. HTTP停止时执行同一清理流程；页面刷新只恢复快照，不创建新任务。当前浏览器页面关闭/连接丢失超过15秒停止活动测试和预览，记录 `client_disconnected`；其他页面只读，不因打开第二个页面自动接管控制。

## 7. 实施步骤 3：真实事件、聊天与时延

在 `bridge.py` 实现小型实例级包装器，保留原方法参数、返回值和异常：

- `ObservedBus.post`：先投递原事件，再把轻量副本发送观测通道；不能调用get抢队列，不能阻塞采集线程。内部音频samples不发给网页。
- 用 `PartialText` 更新同一个右侧气泡，`UtteranceRecognized` 将其标记最终结果；完整text来自事件，不从80字日志截取。每段保留utterance_id。
- 包装 `ChatSession.ask/ask_stream` 观察回答与delta；同一turn只更新一个左侧气泡。生成内容和已播内容分开标记，不能把生成结束当成声音播完。
- 非聊天路径的视觉、提示、拒答等语音文本从包装TTS的 `synth(text)` 及播放事件补齐；通过turn_id/piece_id去重，不重复显示模型流式文本。取消后保留已显示文字并标记中断，迟到delta不复活。
- 包装evidence.write同步保留原始证据，并映射已有状态/取消/错误事件。只调用原逻辑一次，不重复触发播报或重试。
- 测量包装 ASR、Scene/OCR、Chat、TTS 调用起止，使用 `time.monotonic_ns`；线程间保持同一主机单调时基。已有音频结束时间可用于软件首声延迟，但必须在字段标明measurement=software。
- 真实声学首声/停声无法从软件事件直接得出，未测保持null；界面展示“未测量”。不把各模块相加充当总耗时，流式阶段存在重叠。
- 单轮事件绑定run_id、turn_id和图片frame_id。停止、取消、换任务后返回的旧结果只写旧运行记录，不更新当前会话。

回归：模拟PartialText→Final产生一条完整右气泡；多个delta只产生一个左气泡；超过80字不截断；取消后迟到事件不更新；HTML样本文本按textContent渲染。

## 8. 实施步骤 4：共享相机与上传图片

### 8.1 相机

1. 打开页面不打开相机；用户点“开启预览”才采集，按钮切换成“停止预览”。综合测试开始前提示会按需使用摄像头，实际业务需要取图时才打开。
2. 一份 `V4L2Camera()` 实例归 `CameraHub` 所有，只由一个采集线程调用grab。不要为预览和模型分别打开设备。
3. CameraHub缓存最新RGB帧、frame_id和实际t_capture_ms。预览最多每秒编码5帧为JPEG，保留最新一帧；慢浏览器丢弃旧预览，不堆积队列。不把预览每帧写磁盘。
4. 传给现有 `CameraFrameProvider` 的camera适配器，grab返回本次请求开始后到达的有效新帧，保留原始时间、分辨率、source。现有质量门控/重拍继续工作，不为了预览绕过。
5. 模型左框只在实际provider.acquire返回、该帧进入业务请求时更新。记录frame_id、捕获时间、用途、槽位；不得从实时预览端点临时另抓一帧冒充。低质量帧若实际用于分析，要反映其质量状态。
6. 左框提供A/B紧凑切换用于现有双图业务，单图只显示当前帧。停止实时预览不清除本轮已用帧，也不取消已明确允许的综合测试按需取图。
7. 无帧/超时/设备忙显示原因；失效预览不继续伪装实时画面。预览停止后若没有其他相机使用方，关闭设备。

### 8.2 上传

1. 保留 A/B 两槽，上传支持 JPEG/PNG/WebP。浏览器校验之外，服务端同时验证大小、真实解码格式、像素数；禁止SVG、任意路径、伪图片和解压炸弹。
2. POST原始图片字节，服务端用随机ID命名，忽略客户端路径。PIL验证后按EXIF方向规范化，存入uploads；响应只含内部ID、尺寸、格式和槽位。图片显示使用同源内部ID路由。
3. 选择图片完成上传和预览，不自动推理。**上传文件不改变综合测试的真实相机输入**；上传图用于视觉/OCR/比较调试，在调试模块明确选择“相机/已上传图片”，这个选择是输入来源，不是设备选择器。
4. 开始调试时冻结所选图片ID，替换/移除槽位不改变正在执行任务；用过的图复制或硬链接至本轮runs/media，避免后续预览错配。不将上传时间当作真实拍摄时间。
5. 无图片运行返回422；B可选，双图比较必须同时有A/B。删除只清理测试台拥有且不被活动任务引用的文件。
6. 绑定新的图片输入时作废旧比较结果。来源以框标题/tooltip和日志标记，不重新增加大块说明。

## 9. 实施步骤 5：API与前端绑定

以下是**本任务新增接口约定**，不是声称项目已经存在这些API。实现到server.py，前端只请求同源相对地址。

| 方法/路径 | 请求 | 成功结果/行为 |
|---|---|---|
| GET `/api/health` | 无 | 200，HTTP版本、ready；不初始化业务模型 |
| GET `/api/state` | 无 | 服务、设备、当前任务、资源、时延、图片槽位与服务端时间 |
| GET `/api/events?after=N` | seq游标 | 最多200条增量和next_seq；旧游标超界返回reset_required，随后取快照 |
| GET `/api/session` | 无 | 本轮聊天完整快照，含turn/utterance和最后seq，刷新去重 |
| POST `/api/run/start` | `{request_id,mode:"live"}` | 202与run_id；仅接受真实链路，缺音频/模型返回明确错误 |
| POST `/api/run/stop` | `{request_id,run_id}` | 202 stopping；已结束幂等返回200；不接收任意PID |
| POST `/api/preview/start` | `{request_id}` | 202，用户显式开始预览 |
| POST `/api/preview/stop` | `{request_id}` | 200，释放预览引用 |
| GET `/api/preview.jpg` | 无 | 最新JPEG，禁缓存；无帧204；断开503，不自动开相机 |
| GET `/api/frames/{id}` | 内部frame_id | 本轮实际输入图片；仅本目录注册的ID可读 |
| POST `/api/uploads?slot=A或B` | 图片原始字节 | 201，image_id/width/height/slot；不执行模型 |
| DELETE `/api/uploads/{id}` | 无 | 清空对应槽位，正在引用则延迟回收 |
| POST `/api/debug/start` | `{request_id,module,input}` | 202与run_id；固定module白名单，禁止任意Python/命令执行 |
| POST `/api/client/heartbeat` | 当前控制会话 | 活动期间每5秒；断开超15秒停止设备任务 |

所有JSON使用UTF-8。错误体统一：`{"error":{"code":"device_unavailable","message":"默认麦克风不可用","retryable":true}}`。常见错误：400参数错误、409忙/冲突、413超限、415格式不支持、422缺输入、503设备/模型不可用、504超时。异常只返回必要说明，不返回凭据和完整栈。

状态最少字段：

```json
{
  "run": {"id": null, "mode": null, "status": "idle", "started_at": null},
  "services": {"model": "ready", "interaction": "idle"},
  "devices": {"audio_in": "unverified", "audio_out": "unverified", "camera": "closed"},
  "metrics": {"sampled_at": null, "worker_rss_bytes": null, "model_rss_bytes": null,
    "bench_rss_bytes": null, "cpu_percent": null, "gpu_percent": null, "temperature_c": null},
  "timings": {"asr_ms": null, "vision_ms": null, "generation_ms": null,
    "tts_ms": null, "playback_wait_ms": null, "acoustic_first_audio_ms": null},
  "last_seq": 0
}
```

状态值：idle/starting/running/stopping/completed/interrupted/failed；服务就绪与设备已实测分开。事件格式：`seq,run_id,turn_id,type,ts_mono_ms,payload`；type限定state/asr.partial/asr.final/assistant.delta/assistant.final/playback/frame/timing/log/error。

前端：500ms非重叠轮询状态和事件，请求未完成不追加同类请求；失败显示断线，恢复后先拿快照和游标。服务端时间用于显示运行时长。页签切换不启动任务。预览开启后按最高5fps拉最新JPEG，隐藏页面暂停预览拉流但不偷偷停掉综合测试；离开页面用心跳超时收尾。

前端移除所有硬编码聊天、定时假结果、假资源数据。保留上传本地预览能力，但“上传完成”必须以服务器成功返回为准。文本和日志用textContent，禁止innerHTML渲染模型输出。

## 11. 实施步骤 7：资源、日志和结果

- 资源每2秒采样。由/proc读取进程RSS与CPU时间，CPU定义为所有核归一化后的0–100%，同时在tooltip标注。分别统计业务worker、已有模型服务、HTTP测试台；不能重复计入模型进程。
- Orin内存共享，RSS不能直接等同完整CPU/GPU占用。界面将当前“交互进程内存”与“测试台自身内存”按字段显示，模型RSS在tooltip/详细记录给出；不据此宣布4GiB预算通过。
- GPU/温度读取当前可读sysfs节点；无权限或无可靠节点显示null，不sudo、不以CPU值代替。可复用已存在的资源采样工具，但必须证明其只读且无测试台外写入。
- 每轮 `events.jsonl` 保存真实事件，`metrics.jsonl` 保存采样，`result.json` 包含模式、起止、状态、人工确认待定、错误、输入ID、软件测量口径和未测项。
- 浏览器只保留最近1000条日志；清空显示只重置浏览器显示游标，不删除磁盘证据。日志按10 MiB轮转，最多5份；证据每轮最多100 MiB，达到上限停止本轮并说明，避免静默丢证据。
- 不录制全程视频，不默认永久保存完整音频。显式音频调试样本、本轮实际模型输入图可保存在run目录。普通日志不记录密码/令牌，不重复倾倒音频数组或图片base64。
