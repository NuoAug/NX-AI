## 一、唤醒与开始交互

正常唤醒

1. 用户通过当前配置的唤醒词发起交互；现有资料中的名称为“小冰” ↓
2. 有效唤醒后播放本地预置回应“我在” ↓
3. 回应实际播完，尚无问题则开始10秒初始等待；已有可靠问题则直接进入第二章 ↓
4. 用户说出需求，按第一章“收音、短指令与自然停顿”接收完整意图，再路由到聊天、视觉、读字、计算、日期、比较或场景寻物。

同一句包含唤醒词和完整问题时，保存可可靠分离的问题，不要求重说。不能可靠分离才请用户再说问题。回应或提醒被用户打断不算播放故障，不因此丢弃刚说的内容。正式设备以语音完成正常流程，不要求看屏幕、敲字或上传照片。

疑似唤醒处理

1. 系统检测到疑似唤醒 ↓
2. 只确认一次：“你是在叫我吗？” ↓
3. 提示实际播完等待10秒，根据回应处理：
   - 明确在叫系统而未说问题 → 进入初始等待。
   - 已有明确需求 → 直接处理。
   - 无关、仍不清楚或无回应 → 说“有需要再叫我。”并退出。

退出后30秒内不重复疑似唤醒提示，有效唤醒仍正常受理。没有唤醒迹象时不主动提示。

初始等待与延长

- 初始等待10秒，第7秒尚未有效开口时提示：“我在，想聊什么就告诉我。”提醒占原时间，不能因播完而延后截止。
- 用户在截止前有效开口时冻结本次等待剩余量；识别结束后，根据真实意图处理，噪声或附和只恢复原剩余量。
- 只有在本初始等待状态，“等等”才使用每次增加15秒、最多3次的规则。延长后的剩余量为“开口时冻结的剩余量＋15秒”，从指令处理完成时恢复计时，不向已经过去的绝对截止简单加时。
- 两次成功延长按识别确认时刻计，间隔须超过8秒；首次不受间隔限制。间隔不足或3次已用完时不延长，也不提前丢弃仍有的时间，只简短说明仍在等待。
- 第1、2次成功延长后在新截止前3秒提醒“没关系，我再等你一会儿。”；第3次改为“我还在这里，准备好了就告诉我。”撤销旧提醒，不重复叠加。
- 剩余等待耗尽且无正在处理的有效回应时，提示“那我先不打扰你啦，需要的时候再叫我。”然后回普通监听，不要求用满3次。
- 这个结束提示期间，有效新问题可撤销尚未完成的空闲退出；噪声或附和则完成退出。该宽限只适用于尚无实际任务的初始等待，不恢复已终结任务。

收音、短指令与自然停顿

1. 已可靠确定完整意图且用户已经停顿时即可提交，不强制等满5秒；语义尚未完整或端点不确定时，继续收音，以连续5秒静音作为该段提交兜底。若提交后仍缺必要信息，只按第二章澄清，不猜补句尾。
2. 明确的“停”“取消”等短指令走第八章；临时识别片段可以使普通声音暂时让出，但只有完整、可靠的意图才能改变任务或主控状态。否定、引用和“不是让你取消”不能按关键词执行。
3. 单段音频最多40秒。到达上限提交这一段并保留已接收内容，用户继续说时接收后续段，归入同一问题的补充；更新问题版本，作废被后文否定的草稿。用户仍在说话、后段尚未识别或句意未完整时，不把前半段作为最终答案播出。
4. 已确认的分段文本可合并，临时音频在识别完成后释放，不无限积存录音。输入超过本地可接收容量或收音中断时，停止将后续内容记为“已收到”，明确说明已保存到哪里并请求分次补充；不声称完整接收、不据残句执行动作。
5. 每次识别最多10秒；仅临时故障可间隔1秒再试1次。普通输入重说规则见第二章“语音识别失败”，免唤醒候选只使用第十章“免唤醒候选的独立预算”的独立预算，不叠加普通重说轮数。
6. 到期前开口可保留本次回应机会；开口证据与普通截止同刻时先接收，晚于截止则按到期后的状态处理。图片任务、证据及主控事实的硬期限始终继续，开口不能延长它们。

全局事件与提示规则

- 普通监听默认只受理唤醒；第十章有效续接窗口是明确例外，不将所有环境对话送入问答。
- 每次输入绑定其服务的会话、问题、任务和进入前状态。重说、澄清或提示完成时先检查归属，旧事件不能退出或覆盖新状态。
- 同刻先排除失效归属，再处理有效的明确取消/整体重来、已经发生的硬截止、有效回应、普通等待到期。高优先级主控事件按12.4独立受理，不受普通任务事件排序阻塞。
- 每个任务当前只使用一种用户回应等待；允许任务硬期限、双图累计采集预算与该等待并行，但不能同时运行两套准备/额外/恢复回应钟。前台只有一个普通发声与对话焦点。
- 回应等待从对应提示实际播完开始；阶段内提醒占用原等待，提示没有播完就到期时停止旧提醒，执行唯一的到期出口。收音期间撤销过时提醒，不积压补播。
- 必须让用户听到的准备或确认提示最终播放失败，进入设备异常处理，不假定用户同意；已有本轮可靠准备表达时，无需再靠重复提示取得同意。
- 唤醒回应与所有普通提示统一使用第二章“播放、设备恢复与故障收尾”播放规则：从未开始才可自动整段重试；部分或状态未知不直接从头重播。唤醒回应异常后，已有可靠问题则保留并处理；无问题且输出可用时进入初始等待，输出不可用则设备恢复。用户主动打断不重试。

## 二、普通语音问题与回答

需求处理与正常完成

1. 接收话语，区分聊天陈述、问题、补充纠正、独立新问题和控制指令。问候、分享感受、表达想法可直接自然回应，不因不是问句就追问“你想问什么”。纯附和不强制生成新一轮回答 ↓
2. 补充或纠正更新对应条件，只作废受影响结果；独立问题打断图片任务先按第三章“新问题打断、容量与在途操作”保存；停止、取消、继续分别进入第八、九章 ↓
3. 先检查已有有效信息：语言、口述条件或可信已确认文本足够就直接处理；缺视觉证据才进入第三至七章；查看场景和视野内寻物进入12.2。对象或必要条件不明才澄清 ↓
4. 按当前问题及有效来源组织回答，优先回答用户关心的点，可按完整语义片段生成、合成并顺序播出，不必等整篇长文才开始。金额、日期、对象归属必须先确认后播报，不能把待核实猜测先说出来 ↓
5. 生成、合成、开始播放、实际完整播放分别记录。单个片段播放完不等于整轮完成；所有必要内容生成完且实际播完，才能执行一次正常完成收尾 ↓
6. 图片问题先执行第三章“完成、取消、到期与收尾”的完成收尾；有本会话可访问的待恢复任务则进入第三章“新问题后的恢复”，否则进入第十章10秒倾听。纯语音问题无需创建图片任务。

回答长短随需求，用户说“简短点”“详细说”“只读这一行”就调整本次范围，不默认展开所有信息。普通问题被另一独立问题替代时保留必要话题事实，不建立无界的待回答问题栈；“等会儿继续刚才的回答”只保留一个明确的普通续播目标，图片任务各自保留其有效输出。

有限澄清

同一个问题的缺项追问预算跨聊天、OCR、价格、日期章节共享，不因路由变化重置：

1. 先问影响当前回答的必要缺项，最多2轮，每轮提示实际播完等待15秒；明确后直接返回处理。
2. 仍不清楚时，能形成候选就给1～2种理解，进行1轮15秒理解确认；不能形成候选则跳过，不编造候选。
3. 只有一种候选，“是/嗯”可确认；有两种候选，只说“是”不能替用户选择。否定、仍含糊或两候选未选明，进入后续追问。
4. 后续最多3轮，每轮15秒，只追问尚缺部分。仍不明确则结束当前问题。
5. 任一轮15秒无回应：已确认信息足以唯一支持回答则回答，否则说明缺项并按第二章“澄清或识别无法继续时的归属”退出。

一个提示和本轮回应处理计一轮；部分回答、无关回答及含糊肯定计入本轮。噪声只恢复剩余等待，“等等”不延长，不重置轮数。专用控制、恢复、容量选择采用各自更短的两轮预算，不再转入本节取得额外轮数。不得猜数量、价格、优惠资格、日期和目标归属来补缺。

澄清或识别无法继续时的归属

1. 核对本次输入所服务的事情及进入前状态 ↓
2. 澄清或识别无法继续时，按所属事情处理：
   - 当前问题的必要事实仍不明确 → 说明缺什么，终结该问题；若它属于未完成图片任务，执行第三章“完成、取消、到期与收尾”信息不足收尾，不遗留采集任务
   - 只是准备/恢复阶段的一次指令听不清 → 不视为取消，回该任务原阶段及冻结的剩余等待；原硬截止已到则结束
   - 取消对象、继续对象等控制歧义 → 不执行含糊动作，按第八章“控制歧义与回到原状态”回原状态或有界暂停，不一律回普通监听
   - 插入的独立新问题失败 → 结束新问题，仍有可恢复图片任务则第三章“新问题后的恢复”，否则普通监听
   - 免唤醒候选未通过 → 只结束候选，按第十章“免唤醒候选的独立预算”处理，不影响旧任务的独立期限

理解失败提示“我还没确定你指的是哪一个，这次先停在这里。”；缺事实提示“还缺【必要信息】，现在不能确定【结果】。”；系统故障提示“我这边暂时没能完成这次回答。”；无输入使用等待或结束提示。文案可以自然变化，但不责怪用户“整理思路”，不把故障提示写成实际不会等待的确认问句。

语音识别失败

- 没有有效语音：使用当前等待规则，不对空音频重试。
- 有语音但内容不清：请重说，不反复识别同一音频猜内容。
- 识别临时失败或超时：保留本段音频，间隔1秒技术重试1次，每次最多10秒；成功只受理一次。
- 普通输入仍失败：提示“我这边刚才没听清，方便再告诉我一次吗？”，每次等15秒，同一待接收问题或指令最多请重说2次。成功清零本次输入重说次数；用尽或无回应走第二章“澄清或识别无法继续时的归属”。
- 技术重试不重置重说次数；取消、归属失效撤销重试。音频在本次处理结束后释放。用户主动关麦不自动重新打开。

生成与合成失败

回答生成失败

1. 回答生成每次最多60秒，到期或失败时检查已有结果 ↓
2. 按结果处理：
   - 已有完整有效答案 → 直接复用。
   - 没有任何有效答案或片段 → 原问题及来源仍有效时，间隔2秒技术重试1次；本次重试机会已用完则故障收尾，不另开重试次数。
   - 只有部分且尚未播出 → 可作废不完整版本，间隔2秒技术重试1次。
   - 已播出部分 → 说明回答未完成，进入第九章重新回答确认，不自动从头重复。
3. 技术重试的结果与中止处理：
   - 成功 → 使用有效答案继续合成与播报。
   - 仍失败 → 故障收尾。
   - 取消或新意图到来 → 撤销旧重试。

语音合成失败

1. 每个语音片段合成最多15秒 ↓
2. 合成失败后保留答案文本，间隔1秒对同片段重试1次 ↓
3. 根据重试结果处理：
   - 成功 → 不重跑模型，使用该片段继续播放。
   - 仍失败 → 按第二章“播放、设备恢复与故障收尾”收尾。

合成成功但播放失败按播放故障处理，不算合成失败。补充和纠正使旧片段失效时，不再继续合成或播出它。

主动暂停导致的操作中止按第三章“新问题打断、容量与在途操作”处理，不冒称技术失败，不因此获得完整新预算。

播放、设备恢复与故障收尾

1. 确认从未开始播放的音频，可以间隔1秒重试1次；部分播出或结束状态未知，不自动整段重播，保留可信位置，按第九章续播或确认重答。
2. 已知音频时长加5秒仍没有完成/失败回执，停止该实例并记状态未知；无法获得时长的音频不进入正式播放。未知不能写成已播完。
3. 用户打断、取消、旧版本失效不触发技术重试。故障说明使用独立本地预置短音频，最多尝试1次，仍受播放截止约束；不能发声则记录未送达，不循环调用故障链。
4. 相机、收音、输出或必要连接临时失效时，同一次共享设备异常只启动一次恢复流程，最长30秒；受影响的每个现存任务计入一次恢复机会，每任务最多一次。后加入且依赖该故障设备的请求，先说明设备恢复中；若在容量范围内受理为等待任务，就沿用本次恢复的剩余时间并计一次机会，不启动第二个恢复钟；不能受理则明确说明本次不可用。
5. 冻结受影响任务的阶段等待和双图采集累计；操作自身截止、图片及任务硬期限继续。不依赖该设备的任务可继续，不能为修复相机停止可用的普通聊天。
6. 30秒内恢复且任务仍有效，先保留有效照片、答案和原剩余预算；针对当时前台受影响任务问一次“设备恢复了，要继续刚才的任务吗？”，等15秒。明确继续直接恢复；取消、拒绝或无回应则结束该前台受影响任务。后台受影响任务继续保留，轮到恢复时按第三章“新问题后的恢复”询问，不对每个任务重复播设备提示。
7. 前台已转为不受影响的新问题时，不抢播恢复确认；原图片任务在新问题结束后按第三章“新问题后的恢复”处理，原硬期限继续，不能额外叠加15秒设备确认和120秒恢复确认。
8. 30秒未恢复、同一任务第二次设备异常、状态损坏：只结束受影响任务。权限撤销或用户主动关闭设备时不自动重启；关闭收音则终止依赖语音继续的等待，不自动开启麦克风。
9. 故障期间有效取消仍处理。无任务时只停用不可用入口，恢复后普通监听，不凭空创建恢复任务。服务重启后无法核实归属的在途任务及旧输出全部失效，不自动播旧答案。
10. 不可恢复问题按第三章“完成、取消、到期与收尾”终结和清理；普通文本可按第九、十一章有限保留。不能发声、提示被打断或超时，都不能阻止清理，也不能中止其他正常任务。

## 三、单图视觉问答

正常流程与按需准备

1. 保存用户问题、目标、条件和来源。已有可访问且适用的照片、用户没换物且未要求当前新画面时复用；已经明确要求重拍则优先进入第三章“重拍、补看、换物与整体重来”，不被缓存命中绕过 ↓
2. 确需新图时先判断目标和当前准备意图。用户明确要求查看眼前/当前指定目标，或说“已经放好了，现在拍”“再拍吧”，直接取图，不重复询问。仅问“多少钱”而对象不明、需要摆放调整、恢复后准备不可靠时才问准备。场景与寻物使用12.2，不要求把环境放到面前 ↓
3. 必要时提示“把要看的东西放到面前，准备好了告诉我。”并进入第三章“统一准备与额外等待”；明确准备后发起一次取图及可用性检查，合计最多10秒 ↓
4. 无图进入第三章“拍摄预算与有限失败处理”；有图先判断能否支持本问题，足够就分析，部分可答则明确限制；确需重拍时使用剩余次数。连续两次确认模糊且还有次数时采用第三章“拍摄预算与有限失败处理”擦拭提示，不同时再走一轮普通重拍 ↓
5. 图片分析并生成回答使用第二章“生成与合成失败”的60秒及一次技术重试；OCR、裁剪和分析都沿用当前证据，不各自新增拍摄额度 ↓
6. 只回答可靠内容。完整播完执行第三章“完成、取消、到期与收尾”正常完成；部分可靠答案已明确说明缺项时记录“部分回答/未完整满足原要求”，不能把它标成全部比较或全部读取成功 ↓
7. 收尾后，有可访问的暂停任务则第三章“新问题后的恢复”，否则第十章。

拍摄预算与有限失败处理

- 单目标采集最多3次；双图每个位置最多3次。实际发出取图请求即计一次，首次、失败、超时、主动中止和重拍都计入。检查缓存、询问准备、提示擦拭不计次数。请求在发出前被取消则不计；是否已发出无法确认时保守计为已用，不盲目补发。
- 每个图片任务自创建起最长15分钟，包含新问题、暂停、恢复及播报。共享旧图的追问还受原证据期限与原采集剩余预算约束，见第十一章；不能通过换问法重置原图时间或拍摄次数。
- 没收到照片：先检查剩余次数；有次数提示“刚才没收到画面，准备好了我们再试一次。”再回准备；没有次数则说明本次无法确认。不得先承诺再拍，随后才发现预算已经用完。
- 明确相机或连接故障进入第二章“播放、设备恢复与故障收尾”，恢复不补回已消耗次数。所有取图完成先核验当前任务、位置和操作版本，旧结果不得成为新拍摄成功。
- 同一目标连续两次确认模糊且还有次数：最多一次提示“要不先轻轻擦一下摄像头，我们再试试看？”不把此建议说成已确定镜头脏污。愿意则等擦拭后准备好；不愿或不能擦拭可用剩余次数重拍，或仅回答已有可靠部分。中间无图或其他失败中断“连续模糊”计数，不重置总次数。
- 擦拭后的实际取图仍计数，没收到照片不能退回次数。单图与双图只复用本节的判断、提示和次数规则，准备与额外等待统一按第三章“统一准备与额外等待”。
- 次数用完：有相关可靠信息则明确限制后回答；无相关信息则说明不能确认。仅能描述颜色、包装不代表已经回答价格或日期。用户明确重来才建立新采集任务，不自动无限重拍。
- 提示按可靠原因区分：模糊建议拿稳；偏暗/偏亮建议调整光线；未入镜/未拍全建议调整位置；细节太小才建议适当靠近。原因未知用“这次画面还不足以回答你的问题”；没有收到照片不说成模糊。不要求视障用户自己看屏幕判断。

统一准备与额外等待

单图、读字、双图每个位置、补看和场景调整共用：

1. 每个必要准备阶段60秒，从准备提示实际播完开始；按未暂停的累计等待量，第20、45秒仍未准备好时分别短提醒，各最多一次。只有剩余有效等待才可提醒，不能靠提示播放延长；暂停恢复后不重新播已经用过的提醒。
2. 明确准备好直接取图；“嗯”在“准备好了吗”的明确是非语境中可表示肯定，普通附和不算；“继续”只有当前唯一动作明确是拍摄时才算准备好，其他情况先按第八章“控制歧义与回到原状态”澄清。
3. 用户明确要求稍等，若本图片任务尚未使用额外等待，退出当前准备钟，回应后进入一次120秒额外等待；剩余30秒提醒一次。第一件、第二件、重拍和恢复后共用这一次机会。
4. 额外等待中重复“再等等”只说明仍在等，不重开时间、不累计第二次机会；准备好就直接取图。120秒用完仍未准备好，依据可答部分收尾或说明结束，不返回原60秒继续等。
5. 已使用额外等待后，又在某个正常准备阶段要求等，只保留该阶段原剩余量，不立即结束，也不再取得120秒。
6. 独立新问题、设备异常和控制澄清可冻结该阶段剩余量；回来时使用剩余量。阶段内识别噪声或附和也只恢复剩余量。任务硬期限始终继续。
7. 完成一次实际取图后，确需用户再次调整/翻面/换第二件时可建立新的60秒准备阶段；同一准备阶段被打断、重复提醒、重新识别，不算新的准备阶段。额外等待若尚在进行则继续其原剩余量，不因恢复换成60秒。
8. 无回应到期、准备预算耗尽：有足以回答原问题一部分的事实则说明限制后有限回答，否则提示“这次拍摄先结束啦，想再试的时候叫我就好。”并结束。任务15分钟硬截止已到时立即终结，不再利用失效图生成新的有限回答。

普通准备中的有效发言可按第一章“收音、短指令与自然停顿”冻结回应等待；双图180秒采集预算仍按13.1累计，除非已进入本节额外等待或其他明确暂停状态。

重拍、补看、换物与整体重来

1. 判断用户的完整意图 ↓
2. 根据意图区分处理范围：
   - 明确重拍指定照片 → 确认位置后，旧照片不再作为该位置当前证据；依赖它的未播结论失效。重拍失败也不能默默回退旧图冒充成功；另一位置保留
     - 预算及下一步：检查原剩余次数，按当前准备意图取新图；无次数说明需明确重来
   - 同一物品翻面或补看另一处 → 保持物品身份，旧面可靠事实可作为历史已确认信息保留；新事实绑定新图，不把旧面内容迁移到新面。冲突先澄清
     - 预算及下一步：实际取新图仍用原位置3次总额度；超过额度须明确新一轮，不靠翻面刷新
   - 只替换双图某一件 → 只清掉该位置旧物品关联与受影响比较结论；另一件仍有效。说“第一件其实是右边那件”只在归属明确后修正映射
     - 预算及下一步：原位置次数、180秒及15分钟不重置；新物品当前准备不明才问
   - 全部重新开始 → 明确用户要放弃原任务后终结旧任务及其证据，建立新任务；其他独立任务不受影响
     - 预算及下一步：新任务有新预算，仍遵守两个未完成任务上限；原任务的迟到结果丢弃

“重拍第二张”不被“旧图可用”分支绕过；“看看背面”也不自动变成“全部重新开始”。意图不明按第八章“控制歧义与回到原状态”有限澄清，明确前不清除原证据、不拍新图。

新问题打断、容量与在途操作

独立新问题到来自动保存原图片任务，不再询问是否保留。同目标的补充纠正更新当前任务；两个物品的同一次比较算一个图片任务。

最多同时保留**两个未完成图片任务**，包括前台、暂停及等待恢复；两者都可暂停，让普通语音问题先回答。每个新看图请求受理前，同时检查任务名额及第十一章的证据容量。第三个图片任务到来：描述当前可访问的两个任务，询问结束哪个以开始新的，或继续原任务；最多两轮、每轮15秒。明确结束某个才释放其位置；仍不明或无回应则不受理第三个，不静默丢弃旧任务，按第三章“新问题后的恢复”提示恢复原有效任务。选择前旧任务硬期限继续，到期释放的空位可用于仍待受理的新请求，但仍须满足证据容量；新请求已退出后，空位出现不能自行启动它。

前台一次只运行一个普通问题的重计算流程，后台任务优先保存而非同时长期占用推理资源。不能立即中止的操作隔离输出，等待其原操作截止，不宣称算力已立即释放。

根据原任务进度保存与恢复：

- 尚未拍摄或准备中 → 保存问题、目标、条件、原阶段剩余时间和已用次数；恢复到对应准备阶段
- 取图在途 → 保存操作归属和截止；仍在途不重复发起；合法成功可保存，不能自行继续后续步骤
- 已有照片尚未分析 → 保留有效证据，恢复后直接分析
- 分析在途 → 已完成有效结果就复用；仍在途只等剩余时限；不承诺保存模型内部计算现场
- 主动中止了取图/分析 → 任务仍可恢复；中止操作的迟到结果不再接收。恢复取图另用一次剩余额度；恢复分析仅使用该次原截止前剩余时间，不重新给完整60秒；原截止已到则按原剩余技术重试预算处理
- 已有完整答案尚未播出 → 保存文本和来源，有效时直接播报
- 播报途中 → 保存可信位置、文本及来源；恢复按第九章，不重播已经确认听到的全部内容

结果先完成且合法保存、随后发出的中止请求无效时，保留该结果；中止先成立则结果无效。每个操作只有一个终态。技术失败只使用原剩余重试，暂停不补满次数或期限。

新问题期间冻结原阶段等待、双图累计采集与正在进行的恢复回应等待；操作自身截止、任务和证据硬期限继续。新问题成功、失败或结束后，按第三章“新问题后的恢复”恢复；用户仍在发话时不抢播提醒。

新问题后的恢复

1. 选择最近被打断且本会话可访问的有效任务，提示“刚才【用户原意的事件】还没完成，要继续吗？”；有两个可恢复任务时，提示明确命名此次默认对象。用户也可直接指定另一个。
2. 目标唯一、用户点名、或正在明确询问某个目标时，说“继续”就直接恢复；首次提示、超过30秒和第90秒提醒使用同一规则，不额外重复确认。
3. 同时有两个可能目标而没有当前明确焦点时才澄清，每轮15秒，整次恢复等待最多2轮。否定恢复对象不等于取消；不能选择就回原剩余恢复等待，不重开预算。
4. 初次恢复提示实际播完后，建立该任务本次暂停的120秒恢复等待，第90秒提醒一次；提醒占剩余时间。“再等等”不延长，不调用第三章“统一准备与额外等待”的拍摄额外等待。
5. 该任务已在恢复等待中又被新问题打断，回来继续原剩余量和澄清次数；只有任务实际恢复推进、后来再次被独立问题打断，才形成新的暂停事件，任务硬期限仍不变。
6. 恢复成功撤销本次恢复钟。已有有效照片或答案直接使用；回准备时使用原阶段剩余量。仅说“继续原对比”表示恢复任务，不证明现在已摆好第二件；明确“第二件已经放好了，继续拍”则直接拍摄。
7. 恢复等待到期只结束此次被提醒的任务，转向另一个仍有效且可访问的任务；无其他任务才回普通监听。用户明确“两个都取消”可一次结束两个；含糊“取消”仍按焦点判断或澄清。

完成、取消、到期与收尾

任务结束原因分别记录：正常完成、部分回答/信息不足、用户取消、等待到期、硬截止、故障、明确整体重来。不把到期说成用户取消。

- **正常完成或明确说明限制后的部分回答完成：**实际播完后终结原任务，撤销采集与恢复进度、旧操作及提醒；允许将仍有效证据转入第十一章有界缓存用于新追问，不能将已完成任务重新变为待恢复任务。
- **用户取消、硬截止、故障终结或整体重来：**先逻辑失效，停止本任务操作、普通输出和计时；释放本任务自有且未被其他有效任务引用的证据及临时材料，只保留第十一章允许的历史已确认文字。仅借用正常完成缓存的追问被取消/失败时，释放本次引用，不连带清除原完成缓存；若用户明确要求取消整件事/清掉原图，则清除指定完整证据组并使依赖它的任务回到缺证据处理。证据本身硬到期时所有引用一并失效。
- **准备/恢复到期且未形成可答结果：**标记到期、作废旧操作并释放该任务材料。不能在后台借到期重试或自动开始新任务。
- 结束提示最多一次，无法发起则直接收尾；提示播完、失败、被打断或达到播放截止均完成清理。逻辑失效及大块图片/分析资源释放不依赖提示成功，播报只保留所需短文本/音频。
- 后台任务到期只清理自身，不切换正在处理的前台问题。可在前台结束后的合适空隙简短说明，不积压逐条提示；已经失效的任务不再发恢复邀请。
- 前台结束后仍有有效可访问任务则进入第三章“新问题后的恢复”；正常回答且无待恢复任务进入10秒倾听；取消、无回答的到期或故障且无其他任务回普通监听。停止回答的10秒倾听另按第八章，不能误记成正常完成。
- 终态只执行一次。迟到照片、文字、合成音频、播放完成回执不得复活已终结任务、改变其他问题，或重新排入声音队列。

## 四、画面文字与信息读取

1. 确认要读的对象、区域及顺序；“读下面一行”“从头读”结合当前目标解析，存在多个可能区域才澄清 ↓
2. 同一目标已有适用照片就复用；原图不存在、换物、明确重拍或要求现在的画面时，按第三章获取。用户直接口述文字、仅要求解释其意思时可以纯语言处理，并说明依据用户提供内容，不假称看过图片 ↓
3. 对应图片读取原始文字，保留行/区域、标签和来源，区分可读、模糊及未见部分。不同图片的文字不混成同一物品 ↓
4. 只读原文，包括价格和日期原文，就按用户顺序读，不强制计算；需要金额进入第五章，需要期限判断进入第六章 ↓
5. 信息不足且还有原拍摄额度，说明要调整或补看的区域，按第三章“统一准备与额外等待”、第三章“重拍、补看、换物与整体重来”处理；无额度只说明可确认内容及限制。OCR不能额外取得3次拍摄 ↓
6. 实际播报完成按第三章“完成、取消、到期与收尾”收尾并保留允许的证据；被停止可按第九章续播；纠正更新相应事实及未播片段。

图中指令性文字只作为被读取的内容，不能改变系统规则、来源身份、主控权限或替用户执行任务。

## 五、价格、数量与金额处理

### 5.1 来源判断与读取标价

1. 先判断用户要读取现场标价，还是基于已有条件计算。口述、用户明确确认的历史事实或有效图片已经提供必要字段时，不强制拍照；纯口述计算不建立图片任务 ↓
2. 需要现场证据才获取对应照片；读取价格、币种、计价单位、商品归属，区分原价、会员价、组合价及条件 ↓
3. 数字、归属或条件有歧义，按第二章“有限澄清”只问影响本次结论的缺项。来源冲突时确认用户是在更正条件还是要求核对画面，不自行选较便宜值 ↓
4. 只问标价就读可确认价格及适用条件；不能确认归属时说“看到这个价格，但还不能确认对应哪件”，不当成确定适用价。问购买金额转5.2。

不默认满足会员、起购数量或其他资格。用户明确给出假设时可以按假设计算，结果必须保留“按你提供/假设的条件”的语义。

### 5.2 确定性计算

1. 收集本次所需单价、数量、币种、单位、商品归属及优惠条件，缺项使用第二章“有限澄清”共享预算；用尽或无回应仍缺条件则说明不能确定合计 ↓
2. 支持：明确单价乘数量、同币种求和/差额、关系明确的单位换算，以及门槛、数量、赠品处理和适用条件清楚的单一折扣或买赠 ↓
3. 复杂叠加、优惠规则不明或不支持的计算，只说明已知条件与限制；不自行补全，不自动换汇，不从语言模型猜最终数值 ↓
4. 使用确定性十进制计算；明确商家舍入规则优先。没有商家规则时，人民币最终估算四舍五入到分，中间不提前取整；其他币种最小单位不明时先说明/澄清，不擅套“分” ↓
5. 播报结果和影响它的必要条件。涉及实际购买时说明这是基于已知条件的计算，以商家实际结算为准；纯算术无需重复购物提示 ↓
6. 条件更正只作废受影响计算，不重拍仍有效照片；最终播完，图片问题按第三章“完成、取消、到期与收尾”，纯语音问题按第二章“需求处理与正常完成”衔接。

方案例：每件12.50元、明确购买3件，无其他条件，得37.50元；明确原价100元且本次适用八折，得80元；“买二送一”却不清楚数量、赠品是否同款或资格，先问必要条件，不直接报总价。这些是规则示例，不是实际测试记录。

## 六、日期与可见信息判断

1. 确认日期及标签来自用户口述、已确认文本还是图片。需要核对包装时才获取图片；保留原文和标签，区分生产日期、印刷到期日、保质期、储存条件与批号 ↓
2. 只问原文，读取可确认内容即可；需要计算或比较，先选下列路径，再问该路径真正缺少的条件 ↓

按当前需求选择所需信息：

- 读印刷日期原文 → 原文及可辨认标签；缺字如实说明，不强行补成年月日
- 比较两个到期日 → 两个明确归属的到期日期；不需要无关的生产日期和保质期
- 已有明确印刷到期日，判断剩余期限 → 优先用到期日；另需可信今天日期和时区，不额外索取生产日期
- 只有生产日期与保质期，要求推算 → 两项及起算、日/月/年口径必须明确；标注“按标签条件估算，并非印刷到期日期”
- 起算、月底或闰日口径影响唯一结果 → 仅在规则已明确时推算；未明确就解释不确定性，不擅定月底补齐方式

3. 可信本地今天日期或时区不可得时，使用第二章“有限澄清”询问；不能以设备有时间显示就认定正确。缺年份不默认今年，不从包装外观补日期 ↓
4. 看不清且仍有采集额度时可补拍指定区域；只有信息缺项而无需视觉证据时继续语言澄清。追问用尽仍缺必要条件，只读可确认内容，说明不能唯一计算 ↓
5. 播报结果和限制，不把日期判断当成食品安全、药品适用性或实际储存状态保证。只有日期而没有时刻时，不据此断言当天某时刻已失效 ↓
6. 按第二章“需求处理与正常完成”或第三章“完成、取消、到期与收尾”完成；取消、停止、失败、无回应走各自公共出口，不建立额外日期专用等待链。

方案例：包装已明确写到期日2026-12-01，用户问“到哪天”，可直接回答该日期，不追问生产日期；“2026-01-31起保质期1个月”但无月末口径，不能唯一推定到期日。本节例子不使用当前日期作隐含事实。

## 七、双图实物对比功能流程

### 7.1 正常对比与部分证据

1. 保存原问题、比较项目和两件物品的稳定身份。第一/第二件是任务中的位置，不因为用户移到左右两边就自动互换；纠正映射按第三章“重拍、补看、换物与整体重来”处理 ↓
2. 第一件需要拍摄时，已有明确当前准备意图可直接拍，否则提示“先把第一件东西放到面前，准备好了告诉我。”使用第三章“统一准备与额外等待”的60秒准备 ↓
3. 对第一件按本次比较项目分类：完整支持、部分相关、完全无相关有效信息。完整或部分相关均可继续第二件；部分相关先简短说明“第一件的【缺项】没读清，我先看看第二件，能比较的部分会告诉你。”完全无相关信息先按7.6补拍，无额度则说明不能比较 ↓
4. 提示放好第二件；用户已同时明确准备好则不重复确认。取图后仍按完整、部分、无相关信息分类；重拍第二件保留第一件的有效信息 ↓
5. 两边都有证据后逐项核对：只有两边都可靠支持的同一项目才能比较。完整项目回答，缺项说明；两边虽各有部分内容、却没有共同可比较项目时，分别读已知内容并明确“现在不能完成你要求的比较” ↓
6. 视觉属性比较须有相应图像依据；只依据分别读出的文字进行价格/日期计算，就按实际依据表达，不冒称完成了颜色、外观等双图视觉判断 ↓
7. 回答先说用户关心的结论，再给必要依据和限制；实际播完执行第三章“完成、取消、到期与收尾”，允许按第十一章保留两件证据，取消/到期/故障按对应收尾。

同一位置的部分信息已经足够支持用户所问项目时，不为追求整张照片处处清晰而重拍。用户明确要求继续补足缺项，可在原剩余预算内补拍；不暗中删掉未完成的比较要求，也不把部分回答记成完整完成。

### 7.2 准备、稍等与180秒采集预算

- 每个必要位置准备均为60秒，第20、45秒提醒；整个比较任务共用一次120秒额外等待，规则完全引用第三章“统一准备与额外等待”，不保留旧的15/10/15秒分步询问、重开两分钟或三次一分钟延长链。
- 180秒为**实际处于采集阶段的累计预算**：首次准备提示实际播完开始；第一件已准备、无需提示时从发起首次取图开始。包括普通准备、相关提示、收音识别、准备/目标澄清、取图和可用性检查。
- 明确的额外等待、独立新问题、恢复确认、共享设备恢复、高优先级主控抢占不计入180秒；15分钟任务硬期限始终运行。
- 两个位置已具有可用于本轮完整或部分比较的证据、转入比较分析时暂停180秒；后来明确重拍/补看需要再次采集，就继续使用原剩余量，不重新给180秒。
- 180秒耗尽，不再发出取图；仍在途的该轮采集结果不得越过采集截止用于补成成功。已有证据且任务/图片仍有效时，只回答可比较部分；没有可靠比较依据则说明未能完成并结束。
- 15分钟硬截止先到则立即按第三章“完成、取消、到期与收尾”终结，不能为有限回答继续使用到期证据。拍摄/分析已经进行时再说“好了”，不重复发出取图。

### 7.3 再次要求等待

“再等等”在额外120秒内只继续原剩余量；一次机会已用过，在正常准备状态则只等该阶段剩余量。到期提示使用“这次对比先结束啦”，不称用户主动取消。有照片才可以说暂时保留了照片；恢复等待中的“等等”只按第三章“新问题后的恢复”，不能串入拍摄额外等待。

### 7.4 重拍、换物和整体重来

明确重拍指定位置、同物翻面、只更换某件、修正左右关系，全部按第三章“重拍、补看、换物与整体重来”区分处理。整体重来必须有明确意图；终结旧任务后创建新任务，从第一件开始，新任务仍受容量限制。含糊表达先按第八章“控制歧义与回到原状态”澄清，不先清空两张图。

### 7.5 中途提出新问题与恢复

使用第三章“新问题打断、容量与在途操作”自动保存，不再询问要不要保留；最多两个未完成图片任务，两个都暂停时仍可处理普通问题。新问题结束后使用第三章“新问题后的恢复”的唯一恢复流程，明确目标说继续直接恢复，不使用30秒二次确认。

恢复保留原位置、物品、有效证据、准备/额外等待剩余量、拍摄次数、180秒已耗量和15分钟硬期限。已有足够证据直接比较；需取图且只有任务恢复意图，就回原准备阶段；用户明确当前第二件已摆好则直接拍第二件，不再拍第一件。

### 7.6 不可用照片与主动重拍

1. 先区分用户明确要求重拍，还是系统检查照片。用户明确重拍按第三章“重拍、补看、换物与整体重来”先确定位置并使旧位置证据退出当前使用；不能因为旧图可用而跳过。
2. 系统检查发现足以支持全部或部分项目，就回7.1；完全无相关信息才建议调整、重拍。原因提示及连续模糊擦拭统一按第三章“拍摄预算与有限失败处理”。
3. 核对该位置原剩余3次额度及180秒剩余量；还有预算且准备明确才发起，否则先准备或解释预算已用完。另一位置始终保留有效证据。
4. 新图校验归属后更新本位置；重拍失败不自动恢复已被替换的旧图。双方有共同可靠项目就有限比较，没有则明确无法完成。
5. 翻面补看保留同物已确认事实；新图与旧事实冲突时先解决归属/读取歧义，不拼出互相矛盾的商品信息。每位置总拍摄3次不因换面、换物或失败原因变化重置。

## 八、用户插话与停止回答

插话覆盖的状态

唤醒回应、准备提示、生成、合成、播报、取图、分析、提醒及恢复确认期间，只要用户未关闭收音且入口可用，就保留接收当前用户新输入的能力。模型处理不能把“停”“取消”和新问题阻塞到长回答结束后才接收。

普通声音播放时检测到可信真人开口，先暂时让出声音并保存位置；随后按完整语义和会话归属决定动作。系统自身回声、噪声、明显对旁人的谈话不能作为新问题；确认无新需求后恢复仍有效的原状态。附和不重新启动等待，不生成无意义的回复循环。

当前范围为同一使用者的连续交互；不自动扩展多人会议、多人长期记忆或身份切换功能。其他声音可以触发短暂让出，明确“停下声音”可停止普通输出，但不凭陌生声音继承原话题、读取旧图片或取消其他使用者的任务。主控紧急声音是否可中断遵守12.4，不受普通聊天暂停规则关闭。

意图与动作

1. 接收并识别用户的完整话语 ↓
2. 结合当前状态与任务归属判断意图 ↓
3. 根据意图处理：
   - 纯附和、噪声、回声、明确无关发话 → 从可信位置恢复普通播放或回原等待剩余量；过期内容不恢复
   - 停止当前回答 → 停实际声音、清待播、阻断旧生成/合成输出，保留合法文本和位置；图片任务保持暂停，不能误作取消
   - 明确取消，目标唯一或已点名 → “取消整个比较”终结指定图片任务并按第三章“完成、取消、到期与收尾”收尾；仅“取消这段回答”停止输出并撤销该答案的续播版本，关联图片任务保持暂停，按下方10秒倾听衔接
   - 独立新问题 → 保存未完成图片任务后处理新问题；不保留无界普通问题栈
   - 补充、纠正、改变本次要求 → 更新对应问题版本，撤销受影响未播结论，保留仍适用证据
   - 明确暂停拍摄并需要稍等 → 进入第三章“统一准备与额外等待”的额外等待；不把普通“停止回答”自动变成拍摄暂停
   - 明确继续回答/继续任务 → 进入第九章或第三章“新问题后的恢复”，只有目标含糊才澄清
   - 含糊的“停一下”“不是” → 先临时暂停普通声音，按第八章“控制歧义与回到原状态”有限澄清，不擅自取消图片或行走任务

在“准备好了吗”“要继续这个比较吗”等唯一是非确认后，“嗯/好”可表示肯定；在普通答案中同一短词可以只是附和。有两个选择时“嗯”不能替用户选择。用户的“不是”可以是否定某个事实或目标，不全局解释为取消。

明确停止回答后，若收音仍开启，先给用户10秒倾听机会，不马上播放恢复邀请打断其下一句话；这10秒不与拍摄准备或恢复回应钟并跑。截止前新问题、纠正、继续或取消按意图处理。无回应后：有暂停图片任务进入第三章“新问题后的恢复”；没有则回普通监听，只沿用已有话题窗口，不因停止或这次无输入自动刷新窗口。普通可续播文本按第九章保留；关闭收音不自动开麦。

控制歧义与回到原状态

控制对象或作用不明确，最多两轮、每轮15秒，期间冻结原阶段回应等待，硬期限和原操作截止继续；同一含糊意图不能通过改走普通问答获得额外澄清轮数。明确后直接执行，不再重复确认。

- 明确不是要打断、只是附和/无关声音：回原状态，正在播放就按可信位置续播，正在生成就只等原剩余时限。
- 取消/继续对象仍不明确或无回应：不取消、不猜选；原来是准备、额外等待或恢复等待，则回其原剩余量。
- 原来正在生成/播放，仍不能确认用户是否要停：保持普通输出暂停，使用第八章“意图与动作”的10秒倾听；仍无输入后，有图片任务按第三章“新问题后的恢复”，无图片任务回普通监听，不擅自继续长篇声音。
- 该10秒及恢复等待不是新一轮控制澄清；同一次含糊输入预算用完后再次含糊，只简短要求点明对象，沿用当前剩余等待，不自动再开两轮。明确的新控制意图可重新受理。
- 原任务已经到期或被其他明确指令终结：不回原状态，只说明需要重新开始。前台已转为其他问题，旧澄清不能抢回焦点。

## 九、继续之前的回答

1. 确定是继续图片任务还是续播回答；目标明确直接处理。多个可选目标且无焦点时按第八章“控制歧义与回到原状态”澄清，不因为经过30秒再确认一次 ↓
2. 核对问题版本、使用者、来源、有效期和答案状态。内容被纠正、来源被替换或输出已随任务取消/到期而失效，不能按原答案续播 ↓
3. 已有完整有效答案，直接复用文本；仍在原生成时限内且未主动中止，只等待剩余量；中止的分析按第三章“新问题打断、容量与在途操作”剩余预算处理；生成不完整且已结束，进入下方重新回答确认 ↓
4. 有可信片段内位置就从未播完处继续；只有可信片段边界，提示“刚才那一句可能没播完整，我从这里接着说。”，最多从该片段开头重播；完全无可信位置但有完整文本，先说明需要从头读，最多两轮、每轮15秒确认，同意才从头播 ↓
5. 续播完整结束时，先判断答案所属任务：仍未完成的图片任务执行一次第三章“完成、取消、到期与收尾”完成收尾，再恢复其他任务或进入倾听；原任务已经正常完成、此次只是用户要求重读历史文本，则仅结束本次重读，不重新创建采集进度或刷新原图期限。
6. 无法合法续播时，说明原因，最多两轮、每轮15秒询问是否重新回答；同意后按当前有效信息重新处理，需要原图但已不可用时再准备取新图。否认、无回应或仍含糊则停止本次续播请求，不重复开启确认。因答案不完整而需要重答、用户又不接受时，结束该问题及其关联未完成图片任务；只是拒绝从头重读已有完整答案时保持停止状态，有图片任务按第三章“新问题后的恢复”、无则普通监听。不得从同一恢复事件再次自动提出已被拒绝的重答确认。

普通未播文本和可信位置：已有话题窗口时不超过该窗口剩余期限；尚未形成窗口时从停止输出起最多15分钟；本份旧文本的截止固定，不因随后别的问题或话题刷新而延后。图片任务未播文本还受任务及证据期限约束，取最早者。纠正、明确取消该输出、来源失效提前作废。

已经确认的静态事实和已播答案可在第十一章允许范围内作为“之前确认的信息”被引用，或按用户要求重读已播内容；这不意味着可以继续已失效的未播结论，更不意味着恢复采集。实时距离、通行提示和已过期主控行动信息不得作为当前有效指令重播。

## 十、回答后的倾听与再次进入

正常倾听与话题窗口

1. 正常回答实际完整播完，图片任务先完成收尾；有可访问待恢复任务则第三章“新问题后的恢复”，无则进入10秒倾听。不叠加普通倾听与恢复等待 ↓
2. 截止前有效开口按第一章接收；仍在讲话或处理本次合法输入时不因结果晚到退出。无回应到期可播放两声本地退出提示，然后普通监听；退出提示失败不阻止退出 ↓
3. 已有有效话题时，从本次正常空闲退出建立15分钟免唤醒续接窗口；仅唤醒而未提出需求不建立或刷新。后续正常回答完成、再空闲退出可刷新话题窗口，但不能刷新旧图、旧未播文本和主控事实的独立期限 ↓
4. 图片任务内使用其自己的准备/澄清/恢复入口，不要求每次重新唤醒；原话题窗口自然流逝。取消、失败、被停止和故障不会凭空建立或刷新正常话题窗口。

身份、发话意图与访问范围

- 显式有效唤醒可以开启新交流，不以声纹失败拒绝所有新问题；继承旧图片、旧话题或恢复旧任务，仍须确认属于原使用者。无法确认时只处理本次明确提供的信息，不读出旧任务细节。
- 免唤醒只对已建立可信本地说话人依据的当前使用者开放。依据来自已明确启用的本地声纹资料，或本轮主动唤醒后可可靠建立的当前会话语音特征；不得用环境人声静默替换依据。样本不足就保持不可用，不把唤醒成功等同声纹已建立。
- 身份匹配之外，还须符合当前问答/确认语境、明确针对系统的请求，或能明确续接当前话题。明显在和旁人说话、引用别人的话、无新需求附和，安静忽略；只是听见同一人的声音不等于准入。
- 身份不匹配不暴露旧话题；身份不确定且确有对系统请求，提示“暂时无法确认说话人，请先说【唤醒词】。”同类不确定提示30秒内最多一次，有效唤醒不受冷却限制。意图本身不明确的环境发话不主动连续追问。
- 声纹服务不可用或本轮无法建立可靠依据，退回显式唤醒；原任务数据仍按各自期限保留。旧任务恢复提示只对当前可确认访问的使用者发出，不为陌生唤醒朗读原任务名称。
- 身份不确定而新请求遇到任务名额或证据容量限制时，只泛称“还有未结束的看图任务”，不披露内容；本次无法在容量内处理则明确说明，仍可处理不依赖旧资料的普通语言问题。仅说出唤醒词或清除指令不获得旧会话清除权限；只有可确认属于原使用者的明确清除指令才按第十一章处理。无法确认时保留旧资料至原期限，不自动清除，不后台排队启动本次被拒绝的新请求；用户稍后可重新提出请求。

免唤醒候选的独立预算

窗口截止前有效开口，保存候选及其所属话题；窗口到期不再接纳新候选，但已接纳的候选可在下列有界预算内处理：

候选处理流程

1. 首段收音 → 最多40秒；完整话语提前结束就立即进入后续处理，不等满上限 ↓
2. 首段识别 → 每次10秒，临时故障间隔1秒重试1次，最多21秒；不套用普通输入两次重说 ↓
3. 身份与发话意图准入 → 首段识别后最多10秒；可以提前完成，不必顺序等待全部上限。

整体预算：候选从开口到决定 → 最长71秒，即40＋21＋10；任何阶段明确不通过立即结束候选。

准入通过后，已保存分段和正在继续说的内容进入普通输入流程；不得重复受理第一段。持续发言在准入前的后续段只作临时候选，未通过时按下一段分类释放或提供一次短时重入，不能声称已经接受其全部指令。候选所在旧图或任务先硬到期时照常失效，71秒不为旧证据续期。

明确身份不匹配或无关发话，安静丢弃候选，不提供重入复述。其余不确定或处理超时，不更新原话题、不执行控制；若确有针对系统的请求且已可靠转写，可在提示重新唤醒后保留候选文本15秒，音频识别用途结束即释放。只有重新唤醒者可确认与该候选为同一说话人、且明确要求处理刚才内容时，才使用这份文本；不能确认则只处理其本次新输入，不复述候选内容。15秒内未重新进入即释放文本，不重复开重入机会，也不刷新原话题期限。

连续追问的来源选择

- 已确认文字足够：明确依据之前结果回答，不假称重新看过。
- 问同物原照片的新细节，图片仍在、可访问、版本适用：直接再次分析该图，保留原拍摄时刻和硬期限。
- 图片已释放、过期或需要新面：说明需要再看，按第三章准备和采集预算处理。
- 问“现在”“前面有没有变化”等当前状态：重新获取当前画面或有效主控结果；即使缓存仍在，也不能当成实时观察。
- 指代不唯一：只澄清对象，不先拍照、清图或自行选第二件。话题切换不把旧条件迁移到无关物品。

## 十一、信息保留与来源

任务、证据与话题分别管理

“任务”保存尚未完成的工作；“证据组”保存一个单目标或双图事件的照片与来源；“话题”保存支撑近期交流的必要文本。这三者不能共用一个“有效”标志。

正常完成（含已明确说明限制的部分回答）后，原任务终结并清掉采集/恢复进度，证据可转为有界缓存。**证据最晚有效到所属采集事件建立后15分钟**；首次需要采集的新任务同时建立采集事件，仅借用旧图的新任务不重建旧采集事件。任务内明确新建的采集组从该新事件建立时计时，新组不延长当前任务自创建起的15分钟硬期限，也不延长其他来源的期限。追问、重新分析、正常答案完成或再次空闲均不能给旧图续期。复制或缩放也不能刷新拍摄时间。

完成后的新追问是新问题，引用原证据组而非复活旧任务；需再次用该组拍摄时沿用对应位置的原剩余3次额度、已用额外等待及双图原采集剩余量，受原证据组硬期限约束。这些历史预算属于证据组记录，不是已经清掉的任务恢复进度。用户明确要求新一轮当前观察或整体重来、或原组已失效并在说明后明确准备重新拍摄，才建立新采集组和新预算。不能只因旧任务刚完成就悄悄补满次数。

主控提供的资产租期若更短，必须合法取得可在本地保留的副本；没有副本且租期已到就不可再分析。主控实时测量期限独立且可能更短，绝不延至15分钟。

有界容量与替换顺序

- 最多两个未完成图片任务；前台问题与后台暂停合计计算。每个未完成任务最多一份工作证据映射，引用至多两个来源证据组中的两张图片；映射只记录位置和引用，不另存原图、不计为第三个存储证据组。完成缓存不算未完成任务，但占证据存储容量。新比较复用历史图片时，每张图保留原来源和期限；不得改变另一未完成任务的位置映射，仍被有效任务引用的原图不能随旧缓存条目淘汰而释放。
- 最多保留两个证据组，每组最多两张供后续分析的原图：单目标可保留前后两面；双图每位置保留当前一张。翻面后旧面的已确认文字事实可保留，未读取细节不能凭摘要补出。替换前先保护仍有用且已确认的信息及来源。
- 新任务需要存储时，先清理失效组，再替换最旧且没有未完成任务引用的完成缓存；未完成任务正在用的组不能静默淘汰。两个未完成任务已占满时按第三章“新问题打断、容量与在途操作”选择，不为新任务无限增加图片组。
- 临时取图、分析中间材料只属当前操作，操作完成或失效就释放；不因保留两张原图而长期保存全部视觉中间张量。前台重计算优先，后台只留最小可恢复材料。
- 缓存被容量替换时不强行打断用户通知；再次追问时如实说明原图已不可用，并按需重新拍摄。“保留至15分钟”是上限，不是忽略容量和主动清除的保留保证。

任务名额与证据容量共同受理

1. 新看图请求或当前任务需要新增存储组 → 先核对任务名额，再核对新增图片实际需要的组；只增加引用而不存新图，不虚占第三个组 ↓
2. 先清理失效组，再按原顺序淘汰未被有效任务引用的完成缓存；有可用位置才受理新增采集，不能先答应拍摄后无限等待存储 ↓
3. 名额未满但两个组都被未完成任务引用 → 说明需要先结束哪些可访问任务才能释放所需组，由用户选择继续原任务或结束所列任务以处理新请求。一个组被多个任务引用时，明确涉及的任务，不能仅结束一个就声称容量已释放 ↓
4. 用户明确选择后 → 只终结其同意结束的任务，释放引用，再重新检查容量；原组成为可淘汰完成缓存时才按规则释放。仍不足时使用本次剩余选择轮数继续说明，不擅自扩大取消范围 ↓
5. 拒绝、无回应或选择预算用尽 → 不受理独立新请求，恢复原有效任务；若是当前任务自身需要新组，则返回仍可继续的原步骤，无可继续步骤时说明限制并结束该请求。旧硬期限继续，已经到期的任务不恢复。

同一新请求的任务名额和证据容量选择合计最多两轮、每轮15秒，不分别取得两套预算。选择期间冻结被打断任务的阶段回应等待和双图累计采集，原操作及任务、证据硬期限继续；选择不自动清空旧图。身份不能确认时使用第十章的访问限制，不朗读旧任务名称或提供越权清除入口。

跨历史图片比较

1. 用户要求比较先前分别看过的两件物品 → 核对对象及两张原图的访问权限、版本和期限；必要文字已足够则直接按文字比较，需要视觉依据才引用原图 ↓
2. 两张图分别来自两个证据组 → 保留原组，建立本次比较的两位置引用，不复制图片、不合并原组期限；本次任务占一个未完成任务名额，来源组仍合计两个 ↓
3. 只分析已有图 → 不消耗拍摄次数、不启动采集计时；输出受双方来源中较早的有效截止约束。完成或取消本次比较只释放本次引用，不清除仍有效的原完成缓存 ↓
4. 需要补拍某一位置 → 使用该位置来源组原剩余拍摄次数；本次比较最多使用一次120秒额外等待，且只能在正在准备的位置所属来源组尚有该机会时使用。使用即同时记为本次比较及该来源组已用，换另一位置不能再取得一次；当前来源组已用过时只保留正常准备剩余量，不能借另一组的机会延长。原组已有双图采集预算则同时沿用剩余量。本次跨组比较首次进入必要准备或直接取图时建立一次180秒累计预算，起点和暂停条件同7.2；该预算随本次比较记录保存，保留与释放按本章下方记录规则，完成后基于同一比较继续补拍沿用剩余量。采集时同时扣减本次预算及当前补拍位置来源组已有的采集预算，不扣减未参与本次采集的另一来源组；任一适用预算耗尽就停止新增采集，不给旧位置补满次数或延长期限 ↓
5. 原预算内补拍 → 按第三章指定位置重拍规则处理，并使所有依赖被替换照片的未播结论失效；用户明确要求指定位置开始新一轮观察、原来源失效后明确重新准备，或明确整体重来时，按下方“局部新观察与整体重来”处理，不把三者混为同一动作。

局部新观察与整体重来

1. 先明确范围 → 普通重拍、翻面、换物仍用原位置剩余预算；预算用完或来源失效时，说明限制，用户明确同意该位置开始新一轮观察才新建采集组。“继续比较”本身不表示同意新一轮；范围不明按第八章有限澄清，明确前不清除旧证据 ↓
2. 仅指定位置开始新一轮 → 保留当前比较问题、另一位置有效证据及其原期限；撤销本次比较对被更新旧照片的引用和依赖它的未播结论，不删除其他任务仍在使用的旧照片。新图失败也不回退为旧图冒充当前观察 ↓
3. 检查容量 → 已明确放弃的本次旧引用不再占用保护关系，旧组没有其他有效任务引用时才可按原顺序淘汰；若旧组仍支撑另一位置或其他任务，则继续保护。仍缺存储位置时进入“任务名额与证据容量共同受理”，沿用同一请求最多两轮的选择预算，不自动结束其他任务 ↓
4. 容量允许才建立新采集组 → 新组有该单目标3次取图额度及自建立起15分钟期限；当前比较任务硬期限、本次180秒已耗量和额外等待使用记录保持不变。当前比较的180秒已经用完时，不在原比较内再建组拍摄；说明需要用户明确开始新一轮比较。新组的额外等待机会仍受本次比较最多一次的共同限制；另一旧来源的次数、采集预算及期限不刷新 ↓
5. 按第三章准备、取图和失败处理 → 新图合法取得后绑定指定位置，再按双方当前有效证据比较；容量不足、未同意新一轮或新拍摄失败且无法继续时，仅回答仍有依据的部分并明确缺项，无可答内容则结束当前请求。不得继续声称能够完成依赖缺图的比较 ↓
6. 用户明确整体重来 → 终结旧比较任务、撤销其输出和引用，按第三章收尾，不连带删除其他任务仍引用的材料或正常完成的借用缓存。新建比较任务并重新检查容量，使用新任务预算，从第一件重新采集。用户明确要求“新一轮比较，但保留另一件旧图”属于新建比较并借用历史来源，不当成两件整体重拍；借用来源继续受原期限和预算约束。

上述局部新观察也适用于同一来源组内的双图任务：只改指定位置，双图共用的任务硬期限、180秒与已用额外等待不因拆出新组而刷新。单图明确新一轮观察时结束原采集任务并按新任务受理，不能把普通重拍当成新一轮。当前任务已经终结或硬到期时，不能沿用旧任务进度；用户明确的新观察作为新任务受理，可引用另一件仍有效的历史图。

任一来源提前失效时，只撤销依赖该来源的结论，另一来源仍按原期限保留；能回答的历史文字可说明来源后回答，需要新图则按第三章及上面的容量分支处理。两个未完成任务已满时，先完成任务容量选择，不再并行发起证据容量询问；同一新请求的容量选择合计最多两轮，不因转入证据选择增加轮数。

本次比较的额外等待使用记录与180秒剩余量一并保留，后续沿用同一比较时不重置。原来源失效使其对应结论失效，不能同时抹掉仍未完成比较的预算记录；局部新观察期间保留该记录至当前任务终结。完成后的记录只服务有效来源及近期追问，随相关来源失效或话题清除释放，不建立无限历史比较列表；记录已无法可靠恢复时，不猜测剩余预算或默认为全新预算，只使用已有可靠文字回答，确需补拍则说明后由用户明确开始新一轮比较。

信息生命周期

当前问题、目标、用户条件

1. 保留与使用：对应会话和任务；明确纠正更新问题版本 ↓
2. 失效、释放或转换：取消/到期后不能继续执行；必要的已确认历史文本可留到话题到期，不能当新目标条件

原图及派生图

1. 保留与使用：来源明确、可访问、未过期、与当前问题匹配；历史图只支持历史观察 ↓
2. 失效、释放或转换：原期限、目标被替换、用户要求清除、自有任务异常终结或有界缓存淘汰；只结束借用追问时按第三章“完成、取消、到期与收尾”释放该引用，不删除其他有效引用。只释放交互持有材料/租约，不删除主控原始资产

OCR和已确认静态事实

1. 保留与使用：保留原值、标签、单位、物品与来源图；标明原图是否仍可用 ↓
2. 失效、释放或转换：纠正或来源被否定时作废受影响项；原图正常到期可留下已确认历史文字到话题截止，不能推断未读内容

未完成分析、草稿、待播音频

1. 保留与使用：只属于当前问题版本及有效来源 ↓
2. 失效、释放或转换：新版本、取消、硬截止或操作中止立即阻断；不得写进新轮有效答案

完整未播文本及可信位置

1. 保留与使用：第九章规定的有限续播；图片输出另受任务/证据期限约束 ↓
2. 失效、释放或转换：最早期限、纠正、明确取消或来源失效时作废；未知播放位置不记已听到

已播答案和用户明确确认的历史事实

1. 保留与使用：同一使用者近期话题内可解释、复述、作明确历史依据 ↓
2. 失效、释放或转换：话题结束/到期、用户清除、事实纠正时移除或更新；不扩展成长期记忆

临时语音与候选

1. 保留与使用：识别、有限重试或第十章“免唤醒候选的独立预算”一次重入所需 ↓
2. 失效、释放或转换：本次处理/候选结束后释放，不长期录音归档

主控距离、方向及行动提示

1. 保留与使用：有效实例、可信时钟、归属明确、主控期限内 ↓
2. 失效、释放或转换：播放前及后续片段重新核验；过期、撤销、重启或失联后停止使用，不能凭旧值补实时结果


话题窗到期但图片任务仍在有效准备/恢复时，任务必需的最小文本继续依其任务期限保留；不能据此接纳窗口外无关免唤醒问题。候选在窗口内开口，可在第十章“免唤醒候选的独立预算”预算内保留其必要话题快照；不延长其他材料。近期文本只保留当前话题、两个未完成图片任务和一个普通续播目标所需的事实与摘要，不累计所有聊天全文；摘要无法保留的必要条件在再次需要时明确澄清，不能假称仍记得。

同一物品的当前要求与“回顾之前结果”分开表达。用户只取消某个问题不自动删除所有历史对话；明确“清掉刚才照片/不要保留这件事”则清除指定范围的图和文本、撤销相关待播与恢复信息。范围不明先有限澄清，未明确不执行批量清除；到期清理仍照常运行。

来源与纠正

图片、物品、问题、条件、分析和播报位置保持对应关系；双图结论绑定双方证据及比较项目。口述事实明确标成用户提供；图片文字不是用户指令；模型推断不是主控测量。不得从旧图、别的物品或旧模型输出补当前缺失事实。

单个条件纠正只撤销依赖它的结果；更换某一物品只撤销对应位置及相关比较；不因局部更新而结束整个原任务，取消、到期、故障和明确整体重来仍按各自出口终结。读取和准备播报时都复查来源，不能仅在生成开始时检查一次。

来源图片提前失效但当前问题尚未终结时，先撤销依赖该图的在途分析和未播当前结论；若用户只问已确认历史事实，可基于保留文本明确回答。仍需要看图时，说明原图不可再用；旧组有效且尚有额度时按第三章继续，旧采集组硬期限已到或额度已用完时，只有用户明确新一轮观察/重新准备后才按本章“局部新观察与整体重来”检查容量并建立新组，不自动给旧组续期。当前任务本身硬到期则先终结，不以更换来源延长它。

## 十二、离线边界、场景寻物与主控协作

### 12.1 完整离线运行边界

正式运行在眼镜及随身本地计算设备完成：收音、回声处理、唤醒、ASR、声纹、对话、视觉、OCR、确定性计算、TTS、预置提示、资料管理及必要鉴权。运行不依赖开发电脑、互联网、云端推理或在线令牌刷新。部署前可下载资源；同一设备或配套部件之间的本地连接属于设备内部协作，不能借此把核心计算转移到外部电脑。

启动或恢复时区分哪些能力实际可用：相机/视觉不可用则说明不能看图，仍可用口述条件聊天计算；声纹不可用则回显式唤醒；收音不可用就暂停语音入口；输出不可用明确记录无法发声；本地资源缺失不自动上传数据或转云端。恢复按第二章“播放、设备恢复与故障收尾”，不以无限重载代替明确失败。

当前功能范围为日常自然交流、有限近期上下文、物品和画面问答、读字、读价及支持范围内计算、日期判断、两件物品比较、视野内寻物和已有主控能力转述。不开设新闻功能，不自行建立商场地图/楼宇导航，不自动扩展长期记忆或多人系统。

### 12.2 场景查看与视野内寻物

1. 识别是描述当前场景、找某物、读环境标牌，还是询问真实距离/通行。目标模糊先有限澄清；当前场景请求本身足够明确时直接按需取当前图，不提示把整个环境拿到面前 ↓
2. 通过主控提供的取图能力取得画面；交互不另开摄像头争用。取图及检查仍最多10秒，单次观察任务最多3次实际取图、15分钟硬期限，共用第三章“统一准备与额外等待”准备/调整和一次额外等待 ↓
3. 画面中找到明确目标，描述可靠可见特征及“画面左/右/上/下”等相对位置；不把画面方向自动换成身体行走方向。多个候选时给最多两个可区分特征供用户选择，按第二章“有限澄清”澄清，不替用户选目标 ↓
4. 没看到目标，说“这张画面里还没找到”，不说整个现场不存在。尚有次数时建议在安全、可行情况下调整朝向再看，等用户表示准备好；不会让用户按猜测距离前进。次数用完说明观察范围和限制，结束本次找物 ↓
5. 用户问另一处、要求看现在或转动后继续找，需新画面；用户只问已拍画面细节可按第十一章复用。已找到不等于通路可行，不自动启动导航 ↓
6. 用户进一步问真实距离或请求接近目标，转12.3：先确认视觉目标与主控对象是否可靠关联；关联失败说明当前不能给该目标距离或行走结论 ↓
7. 找到后播报、部分观察、取消、停止、插入其他问题及超时均使用公共收尾与恢复；不会另开无限循环扫描任务。

### 12.3 主控事实与控制意图

主控负责RGB/深度/IMU采集、测距、空间状态、路径和危险判断。交互依据已有 `interaction.v0.1` 合同消费图像和事实，不改变接口职责或自行承诺主控能力已实现。

- 距离、真实方向、通行或行走状态，只转述主控当前有效且对象对应的事实；值缺失或时钟/实例不可信就说明不可确认，不把未知读成0，不用视觉估计补米数。
- 查主控状态或提交明确控制意图时，当前交互最多等待10秒得到结果；主控给出的更早请求截止优先。超过截止说明尚未确认，不说已经执行。迟到响应不算本轮成功、不自动播放旧成功提示；后续查询应取得仍有效的最新状态。
- “开始/暂停/继续/结束引导”等必须来自用户最终有效意图，必要时先澄清。只取消聊天不等于暂停行走；含糊“停一下”先停止普通输出再询问指向。
- 控制结果只有确认完成且实际模式对应才说已完成；仅受理或仍处理中就明确说明。接口提前返回临时超时/处理中、而本轮10秒尚有剩余时，可用同一请求标识查询结果，不重发动作；总等待用完即报告未确认。用户后续明确查询状态可另开最多10秒的查询轮，仍查询原请求，不把查询变成重复执行。
- 服务失联、重启或时钟变化，使旧实时事实及待播行动提示失效；重新建立有效连接后才使用新事实。主控能力缺失则报告不可用，普通聊天和可用图像能力可继续。

### 12.4 安全提醒与普通对话的衔接

1. 只将真实主控来源、仍有效且未被撤销的事件作为安全/引导提醒；优先级和打断策略以主控合同为准。普通模型、OCR和用户话语不能自行生成主控紧急身份 ↓
2. 紧急事件抢占普通聊天及普通导航输出，不等待长模型调用完成。停止旧普通音频、保存可信文本位置，废弃不再适用的排队片段；只允许一个实际发声通道 ↓
3. 收到、入队、开始发声、完整播完、失败分别反馈，不以收到事件冒称用户已听见。普通停止或取消不关闭紧急入口；主控撤销/替代事件时只清理对应事件 ↓
4. 相同事件去重，新事件或明确重复指令仍可受理。过期行动提示不补播。播放后续片段也复查事实有效性，主控状态失效就停止对应旧片段 ↓
5. 抢占期间暂停普通阶段回应等待与双图累计采集，任务及证据硬期限继续；原分析截止不因告警重置。普通新输入可保存明确意图，但不能阻断紧急事件处理 ↓
6. 高优先级声音结束且无仍需优先处理的事件后，先结算已经发生的取消、到期、设备故障及操作完成事件，再处理用户已提出的新输入。新输入仍须经过原入口的身份与意图准入；旧取消、到期和失效状态不恢复。无新输入时按被打断的前台状态依次判断，命中一个分支即不执行后续分支，不能仅因后台有图片任务就跳过前台问题：
   - 设备恢复或设备恢复确认尚未结束 → 继续第二章原流程及剩余预算，不另开恢复确认。
   - 输出、收音或当前步骤必需设备不可用 → 先按第二章处理设备故障；不能先续提示再发现设备不可用。已超时或已结束的设备恢复不重新获得30秒。
   - 当前阶段的必要提示被打断 → 设备可用且原阶段仍有效时，按可信位置续完提示；位置未知时用一次简短提示重新明确当前问题。该阶段等待从未启动才在提示结束后启动；已经启动则只恢复冻结的剩余量。阶段提醒不补播过时内容，不因提示续接增加轮数或时间；提示再次失败进入设备异常处理。
   - 免唤醒候选或短时重入正在处理 → 继续第十章原候选及原绝对截止，71秒、阶段处理上限与15秒重入不因抢占延长；已超时按原失败分支结束，不把候选直接作为已准入问题。
   - 正在普通收音或识别 → 保留已可靠接收的内容；收音未中断且仍在原单段上限内则继续，已达到上限按第一章分段处理。识别已合法完成就使用保存结果，仍在途只等原剩余期限，已经失败或超时则按原失败预算处理；音频中断时说明接收范围，不把缺失部分当已收到。
   - 正在等待纯语音或图片问题的必要澄清 → 回原问题及本轮剩余等待，保留轮数、已确认条件和原任务期限，不额外询问是否恢复整个任务。
   - 初始唤醒等待、疑似唤醒确认、回答后或停止后的10秒倾听、控制或容量选择被打断 → 返回原状态与冻结的剩余等待；原计数、已用延长和提醒记录不重置，不再询问是否继续普通回答。
   - 图片任务正在准备、额外等待、取图、分析、合成或播报 → 进入第三章恢复流程，保留原阶段及剩余预算。取图或分析已经合法完成则保存结果；仍在途不重复发起，原截止已到则按原失败处理，主动中止的迟到结果丢弃。进入恢复确认期间不同时运行准备或额外等待钟；明确恢复后才续原阶段。已经处于恢复等待的只续剩余量。
   - 只有普通回答的生成、合成或播报被打断 → 询问是否继续，实际提示播完等待15秒一次；明确继续按第九章，拒绝或无回应停止普通输出，保留合法文本至原期限；有后台图片任务再进入其恢复流程，无则回监听。
   - 正在等待主控状态或控制结果 → 保留原请求标识及原10秒总截止；已有合法结果先核验当前有效性，仍在途只等待剩余量，超过截止按未确认收尾。不得因恢复重发控制动作，迟到结果不自动变为本轮成功。
   - 已处于普通回答的15秒恢复确认 → 只续原剩余量，不因再次抢占重新询问或增加15秒；原文本已经失效则结束该恢复请求。
   - 原来仅处于普通监听或话题续接窗口 → 回普通监听，话题窗口按原绝对截止继续，不刷新；原任务已终结时，先处理其他仍有效且可访问的暂停任务，无其他任务才回监听。
7. 任务本已在恢复等待中则只继续其剩余量，不再加120秒；恢复前复查问题和来源。仅提醒声音结束不等于危险已解除，不据此播“现在可以走”。

### 13.2 方案层面的完成条件

- 完整：已确认功能都有进入、正常结果、必要缺项、插话、取消、失败、到期和后续去向；场景与主控协作包含在边界内。
- 详细：对象、证据、问题版本、可恢复内容、次数和时间归属明确；同一条件没有两个互斥动作。
- 可行：仅依赖本地能力及已定义主控职责；能力不可用有明确降级，不靠推测或云端补齐。
- 目前最优：按已选取舍减少重复拍摄、重复确认和过多提醒，同时保持任务/缓存有界；不宣称未测性能已经最优。
- 无已知矛盾、逻辑闭合：只存在本版一套规则；有限分支可退出，已终结任务不复活，部分证据不冒充完整依据，后台不覆盖前台。
- 当前阶段仅形成可审核的功能方案。模型选型、具体代码调整、硬件效果及实测验收不在本轮执行；实际实现需要再核对当前仓库，不能据文档推定功能已实现。

### 13.3 主线与交叉场景的预期结果

以下是方案推演口径，不是已经执行的设备测试：

| 场景 | 唯一预期 |
| --- | --- |
| 唤醒和问题同句，回应播放发生异常 | 保留可靠问题，按真实播放状态处理，不要求无故重说/整段重复 |
| 临近回应截止说等等，识别晚到 | 用开口时剩余量＋合法增量恢复；硬期限不延长 |
| 用户聊天陈述、短指令、长句后半段否定前半段 | 聊天自然回应；短指令及时让出；长句合并条件，不播被否定结论 |
| 刚看完包装，马上追问原图另一行 | 图仍有效就再次分析，无图才说明重拍；任务完成状态不反转 |
| 口述价格数量齐全、已有印刷到期日 | 不强制看图，不问无关日期字段 |
| 同物翻面、重拍第二件、只换第一件 | 分别保留同物事实、替换指定证据或更新指定物品，不清掉无关位置 |
| 第一件只有价格、第二件有价格和日期，原问两项 | 可比较价格，明确第一件缺日期，不冒充完整比较 |
| 已有两张可比较图又要求重拍 | 重新进入采集并使用原180秒剩余量和该位置剩余次数 |
| 两个图片任务暂停时再问普通问题 | 回答普通问题；第三个图片任务需容量选择，不静默丢任务 |
| 90秒恢复提醒中明确说继续 | 直接恢复明确目标，不再问同一确认；没有当前摆放依据则回准备 |
| 在途操作为插话而中止，之后继续 | 使用合法保存结果或原剩余预算，不双发、不刷新次数 |
| 停止图片答案后继续，直到最后一句播完 | 先倾听；续播完成执行一次原任务收尾，再进入后续交流 |
| 后台图片到期、前台正在回答 | 只结束后台，不停止前台，不再提示恢复过期任务 |
| 同一人对旁人说话、陌生人唤醒 | 不仅凭声纹回复环境谈话；陌生新交流不继承旧话题 |
| 共享设备故障影响两个任务 | 同一恢复流程、各任务预算有归属，不重复设备提示，不无限重试 |
| 看当前场景/寻找物品后追问距离 | 当前取图；只描述有依据的视野位置，真实距离另取主控有效事实 |
| 普通回答中主控紧急提醒到来 | 优先真实有效提醒，普通取消不关闭紧急入口，之后按有效状态恢复 |
| 分别看完两件物品后要求比较旧图 | 两来源组保持原期限与预算，本次只建两位置引用，不增加第三个存储组；补拍同时受本次及来源预算限制 |
| 初始等待或纯语音澄清被紧急提醒打断 | 返回原状态及剩余等待，不重置次数，不误进普通回答恢复确认；新输入先处理 |
| 一个历史比较占用两来源组，再插入独立看图请求 | 同时检查任务名额和存储容量；明确选择后才释放，不以还有任务名额承诺必能拍摄 |
| 跨来源比较先后在两个位置要求额外等待 | 本次最多一次，且不能借用另一个来源组的机会；同一比较追问保留使用记录 |
| 比较中仅一件需要明确的新一轮观察 | 只更新该位置，先释放本次旧引用并检查容量；另一件有效图及原期限保留，当前任务硬期限、比较累计预算和已用等待不刷新 |
| 局部新观察时比较累计预算已耗尽或任务硬到期 | 不给原比较续期；说明后仅在用户明确新一轮比较时受理新任务，仍有效的历史图可按意图复用 |
| 提示未播完期间发生设备故障和紧急抢占 | 先结算有效状态与设备恢复，设备可用后处理必要提示，不重新启动已启动的等待 |
| 身份不确定者要求清除旧会话 | 不披露或清除旧资料，可处理容量允许且不依赖旧资料的新问题 |
| 生成失败且没有任何有效片段 | 只使用原剩余一次技术重试，仍失败统一收尾 |
| 提示播报失败、被打断、旧回调晚到 | 终结和清理不被提示阻塞，旧回调不复活任务或覆盖新问题 |
