# 无屏可用性走查（2026-11-16，软件层）

## 方法与边界

- 依据当前代码、正式入口（`InteractionEngine._utterance_flow`）、引擎定向用例、真实录音文件回放和真实模型双图集成整理；**不是真人视障体验，也没有声称通过真人验收**。
- 不向测试者提供固定口令，不要求放慢语速；走查中需要看页面、读日志或旁人提示的步骤单独标出。
- 真实录音、拍摄、播放和真人验收仍需用户按轮启动；本轮未开外设、未做行走/通行测试。
- 现有状态机与图片任务存储不变，未新增第二套任务状态。

## 一、状态—声音反馈—可用操作

| 状态 | 触发/事实来源 | 声音反馈 | 用户可说/可做 | 仍缺什么 |
|---|---|---|---|---|
| 待机 | 启动完成、空闲退出 | 首次“小冰”后“我在”；待机不反复播 | 叫“小冰” | 无屏幕时不知道麦克风是否被静音（见阻塞项） |
| 已唤醒/确认 | 唤醒词命中、问候实际播完 | “我在”，播完才进入倾听 | 直接提问 | 环境噪声下唤醒可靠性仍待真人测 |
| 正在倾听 | 问候/回答结束、T1x 窗口 | 不播等待词，避免盖住用户 | 正常语速说话 | 倾听超时/提醒是否足够可感知待真人测 |
| 已接收问题/处理中 | 收到最终 ASR、开始取图/模型 | 暂无“正在处理”播报；等待词不计实质首声 | 可插话、可问“你在等什么”（比较任务内） | 模型处理中问状态会打断当前回答，见剩余问题 |
| 等待第一件 | 双图任务新建、无 A 帧 | “先把第一件东西放到镜头前，准备好了说‘好’‘继续’或‘拍’。” | “好了/换好了/来，看这个”；“先别拍/还没好”；“第一件是什么”；“你在等什么” | 真实相机取景是否清楚待测 |
| 等待第二件 | A 帧已成功采集 | “第一件我看到了。请把第二件放到镜头前，说‘好’或‘继续’再拍。” | 同上；可说“现在是另一件” | 同上 |
| 拍摄成功 | 帧对象实际取得并登记 | 第一件成功后才说“第一件我看到了”；第二件成功后才进入比较，不提前说“拍好了” | 等比较结果 | 无独立“咔嚓”提示；是否需要待真人评估 |
| 拍摄失败 | `FrameAcquisitionError`/`FrameQualityError`/T09 超时 | “第X件这次没拍到，<原因>。<一个调整动作>。第一件还保留着……” | “好了”重试；“重拍第二件”；“算了，不比了” | 目标未入镜/归属不清缺少检测信号，只能降级提示 |
| 正在比较 | 两帧有效、模型/OCR 处理中 | 暂无独立提示；等待词不算实质首声 | 可插话、可问状态（会打断） | 处理中状态询问的打断语义见剩余问题 |
| 正在播报 | TTS 实际提交播放 | 回答正文；首次实质首声按播放提交记录 | 开口可打断普通提示 | 实际声学首声/停声未测 |
| 已暂停 | 用户“先放着，聊点别的” | “好，先放着。想聊别的直接说。” | “继续/好了”接上；插问；“算了”结束 | 暂停期间没有后台取图 |
| 已取消/结束 | “算了，不比了” | “好，不比了。” | 之后“继续”回“现在没有要接着看的图” | 不复活旧任务 |
| 比较完成 | 回答实际播完 | 比较结果正文 | “只比价格/重拍第二件/第一件叫什么/继续” | 结果质量依赖 OCR/VLM，见回答组织 |
| 等待重拍选择 | 问“你想重拍第一件还是第二件？” | 同一句问题 | 只答“第一件/第二件”；“先别拍”；“算了” | 答“第一件是什么”会先回答，不误重拍 |
| 设备/服务异常 | 采集断流、播放故障、模型超时 | 按实际原因播“设备恢复/音频设备出问题/这次比较没看完” | 按提示重试或待机 | 扬声器坏了听不到；麦克风关了无法用语音恢复（阻塞项） |
| 清除资料 | 用户明确“清空/清除资料” | “好，之前的对话和图片资料都清掉了。” | 重新开始 | 清除后历史回落已禁用 |

## 二、无屏任务走查

### 1. 唤醒、确认结束、立即提问
- 目标：叫“小冰”后直接问，不等长问候。
- 系统事实：`GREETING` 播完才进 `LISTENING`；问候音可预合成/缓存。
- 声音：只播“我在”；不播“请说”之类长提示。
- 可用：唤醒后直接说问题。仍缺：真人环境下唤醒率、问候实际播完到首字的间隔。
- 失败：未唤醒时无反馈；用户只能再叫一次。无屏时无法确认麦克风是否被系统静音（阻塞项）。

### 2. 普通聊天、追问、改口和打断
- 目标：正常聊天、追问、改口。
- 事实：聊天走模型；插话会取消当前播报/生成；回答按分段流式播。
- 声音：回答正文；被打断即停声。
- 仍缺：处理中问“到哪一步了”会取消当前回答（见剩余问题）；模型内容质量未在本轮重验。

### 3. 当前画面描述与“刚才那张”
- 目标：知道回答的是当前画面还是旧图。
- 事实：整景观察（眼前/前面/周围有什么）与“现在呢/再看看/变了没”强制新取图；同图追问才复用上一帧；取消/停止清缓存。
- 声音：回答正文；不主动说“这是刚才那张”，只在必要时按来源记录。
- 仍缺：用户无法从声音直接分辨“刚拍的新图”与“复用上一张”；证据里有 `reused/source`，但没有专门播报。建议真人验收时重点问“这是现在的画面吗”。

### 4. 找物与位置描述
- 目标：知道有没有找到、在画面哪里。
- 事实：`FIND` 意图、`find_object` 返回候选；位置用“画面左/右/上/下”，不推断身体左右。
- 声音：先说是否找到，再说有证据的特征与画面位置；不根据单帧说“可以伸手/向前走”。
- 仍缺：目标未入镜与“没有这个东西”的区分依赖检测质量；真人场景未测。

### 5. 读文字、价格、日期和关键数字
- 目标：读指定区域/字段，不编数字。
- 事实：OCR-first；价格/日期结构化；读不清会明说没读到；双图明确价格时不走 VLM。
- 声音：字段名+数值+单位；缺项说明。
- 仍缺：真实包装反光、小字、曲面、局部裁切的成功率未在本轮重验；OCR 目标机测试需模型服务。

### 6. 包装翻面后继续询问
- 目标：翻面后问另一面日期，不拿旧图。
- 事实：明确“翻面/背面/再看”走新取图；同图追问复用；单目标 3 次额度。
- 声音：新结果；旧结果不冒充当前图。
- 仍缺：真人翻面链路未测；翻面后目标是否入镜无检测，只能靠质量/OCR 结果降级提示。

### 7. 双图准备、拍摄、等待、比较、插问、纠正、重拍、暂停、取消
- 目标：不背口令完成两件比较并纠正错误。
- 事实（本轮修复后）：
  - “第一件是什么/第二件多少钱”先回答，不当准备完成；无画面时答“还没有可用的画面，等拍好再问我”。
  - “好了，不过先别拍”“别继续拍”保持等待；“先别拍……现在好了，可以拍了”按最后明确意愿拍。
  - “准备好了没有我不知道”只问一次“你是说第一件已经放好了吗？”。
  - “不是第二个，是第一个”：上一轮问的是第二件时改答第一件，不交换 A/B；上一轮是完整比较时才交换归属；没有比较归属证据时只问一句“改指代还是对调？”。
  - “重拍”未点名时问“第一件还是第二件？”，用户只答“第一件/第二件”即可执行。
  - “只比价格/容量也算上/不比价格看日期”复用两帧，不重拍。
  - 第二件失败保留第一件，给一个调整动作；两次失败提示换一件/稍后再试/不比了。
- 声音：等待、保持、澄清、状态、失败都有一句短反馈；第一次“先别拍”带用法，之后只说“我等你”。
- 仍缺：真人相机取景、真实模型比较质量、复杂纠正（同时改指代和比较项）未测。

### 8. 模型慢、识别失败、相机失败、麦克风或扬声器断开
- 模型慢：T11 超时播“这次比较没看完，你说‘继续’我再接着看”；聊天失败走 T13 恢复窗口。
- 识别失败：空识别重说；连续空识别回待机；不再统一说“没听清”。
- 相机失败：区分取图失败/质量失败（暗/亮/糊/太小/太大），每次一个动作；第二件失败保留第一件。
- 麦克风断开：采集看门狗报 `DeviceFault`，T14 尝试恢复；失败播“音频设备出问题了，我先待机”。
- 扬声器断开：`AudioSink` 报 `DeviceFault("audio_out")`；但声音本身听不到，合同 `playback.status=failed` 只能给主控。**无屏时没有独立恢复渠道，列为产品阻塞。**
- 麦克风被用户关闭：`set_microphone(False)` 同时关闭倾听与唤醒，无法再用语音“打开麦克风”。**当前唯一恢复是主控/重启，列为产品阻塞，未虚构硬件能力。**

### 9. 会话结束、恢复与声纹不确定
- 事实：回答后 T17 倾听，空闲进 T21 话题窗口（需已注册声纹）；声纹不确定要求再叫“小冰”；清除/待机退出话题窗口。
- 声音：提示语来自身份层；未注册声纹时不伪报能力。
- 仍缺：真人声纹注册、本人/他人准入、话题窗口续接未验收。

### 10. 完全不操作网页完成核心任务
- 可以：唤醒→提问→看图/找物/读字→双图比较→插问→纠正→重拍→暂停→继续→取消→待机；状态询问在比较等待/结束时可答。
- 仍需网页/旁人的：启动或停止测试台、选择设备、启动模型服务、查看原始证据、处理麦克风被系统静音/扬声器损坏。
- 结论：核心对话流程可不看网页；但“启动、设备选择、音频故障恢复”仍不是无屏可完成的，属于本轮未解决的产品阻塞。

## 三、本轮修复与仍未解决

**已修（软件层定向）**
- 等待拍摄的整句意愿仲裁：疑问、不确定、否定、引用、过去完成态优先；不再只靠“拍/准备/第一件”关键词。
- 全局控制先于任务层：清除/停止/静音/紧急不会被“好了”吞掉；“取消比较”仍按比较结束处理。
- 插问先答、不取图；状态询问按实际阶段回答。
- 改指代与交换归属分开；重拍待选支持只答“第一件/第二件”。
- 第二件拍摄失败保留第一件；质量标签映射为单一调整动作；两次失败给退出/稍后选项。
- 等待保持有短回执；第一次带用法，之后简短。

**仍未解决/需产品决策**
1. 麦克风关闭后无语音恢复渠道；扬声器损坏后无独立反馈渠道。需要主控/硬件按钮/自动限时恢复之一，属于产品阻塞。
2. 处理中问“到哪一步了”会取消当前回答；当前只在比较等待/结束和普通倾听时答状态。若要非打断式状态播报，需要新的并发播报/主控通道。
3. 目标未入镜、归属不清没有检测信号，只能按“画面里目标太小/画面不够清楚”降级，不能猜方向。
4. AEC 未接入前端，播报中回声是否污染输入未做声学验证。
5. 回答组织（找物/读字/价格/比较）沿用现有实现；本轮没有重写内容质量，真人准确率未验收。
6. 固定提醒与动态回答音色不同；未引入在线 TTS 或新模型。

## 四、真人验收建议（用户启动，单轮≤5 分钟）

1. 不提供固定口令，按自然说法完成：唤醒→问当前画面→找物→读价格/日期→双图比较。
2. 重点复测本文件第二节第 7 条的 6 个反例，观察是否出现误拍、误交换、旧图冒充。
3. 第二件失败时只重拍第二件；第一件应保留，提示应是一个可执行动作。
4. 播报中插话、停止后继续、取消后新任务；结束后说“继续”不得复活。
5. 记录：是否需要重复、澄清次数、旁人介入、误动作、放弃、任务完成情况；不要用测试数量代替真人结论。
