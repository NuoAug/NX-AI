## 一、本阶段交付

同一服务生命周期内串起：音频输入 → 回声参考 → AEC → 唤醒 → VAD → 流式中文 ASR → 本地聊天 → 分段 TTS → 唯一播放器出口，并实现三条路径（只唤醒 / 播完立即提问 / 唤醒词与问题同句）。

## 五、本阶段实际可用

- 目标板上可运行的完整命令入口：`python -m aieyes.main --config config/target.json --replay /path/to/wav`；`--duration` 限制运行时长；无真实音频设备时自动用文件回放。
- llama-server 常驻（`tools/serve_llama.sh`），提供 OpenAI 兼容接口，qwen35 文本 + mmproj 多模态；VLM 请求默认关闭 thinking（`chat_template_kwargs.enable_thinking=false`）。
- 三条路径都能在目标板重复跑通（本批 4 passed / 63.54s）。

## 六、差距与下一步

1. **硬件阻塞**：目标板无麦克风/扬声器，出口 b 的“盒上听到”、出口 c 的“真实播音捕获人声/设备自播对照”无法做。需要用户接 USB 麦克风、扬声器（或确认 HDMI 输出+USB 麦）后，由用户发起一轮真机声学测试。
2. **同句路径的首字损失**：合成句“小冰，一加一等于几？”经 ASR 得“加一等于”（丢“一”“几”），属唤醒词与问题边界处的前端首字保护窗口问题（Barge-in 期间 VAD 起始帧之前丢音）。不影响“只受理一次”的语义，但需要后续扩大/前移 ASR 前置缓冲（阶段 2 与插话一起修）。
3. 纯聊天无画面输入时，模型会自由发挥（如“前面有个人在跟你说话呢。”）——阶段 3 接入取图/OCR 后以画面证据约束回答。
4. KWS 对合成音在整机高负载时出现过一次漏唤醒（单跑与复跑均通过），需要负载下的稳定性验证（阶段 7）。
5. 生成/TTS/播放超时、部分已播、回执丢失、设备故障恢复、否定/纠正、40 秒分段等属阶段 2 范围，本阶段未实现，未伪报。

**下一步**：阶段 2（对话控制）——事件归属与计时、40 秒分段、否定与纠正、插话/停止的真实取消路径（停声/队列清空/旧计算退出三时刻）、设备失效恢复、T13/T14/T17/T18 边界，先做虚拟时钟回归与回放可复现实例。
