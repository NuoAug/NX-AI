## 一、离机运行准备（已完成）

1. **启动与停止**（`tools/run_aieyes.sh` / `tools/stop_aieyes.sh`，说明见 `Docs/交付/运行手册.md`）：
   先拉起 llama-server 并等 `/health`，再 `setsid nohup` 启动 `python -m aieyes.main`；两进程与 SSH 解耦，
   断开开发机不影响运行；停止时先 SIGTERM 服务（正常收尾并写 `shutdown` 证据）再停服务端。
   当前未安装 systemd 单元，重启后需人工执行启动脚本（已在运行手册注明）。
2. **离线依赖审计**：运行期代码无外部 URL（除 `127.0.0.1`）；llama-server 绑 `127.0.0.1:8080`；
   合同服务端默认 `127.0.0.1:18700`（`contract.enabled=false`）；模型/运行器/依赖均在本地。
3. **30 分钟持续检查工具**（`tools/soak_test.py`）：回放「唤醒 → 2 s 静音 → 真人问题 → 24 s 静音」≈30 s/轮，
   驱动真实栈（ReplaySource → KWS/VAD/ASR → InteractionEngine → 流式 VLM → PiperTts → 播放出口），

  且服务端 RSS 在 30 分钟内单调增长（见下）。

## 三、内存超限根因定位

1. **增长发生在 llama-server，且与请求持续进行相关**。
   运行 B 的服务端 RSS 曲线：`3.00 → 3.08 → 3.14 → 3.24 → 3.37 → 3.47 → 3.66 → 3.85 → 3.99 → 4.23 → 4.37 → 4.56 GiB`
   （10:37–11:07，约 35–45 MiB/min，全程单调无回落）。
2. **不是图像/VLM 模态特有**：文本专用 10 分钟同样增长（3.15 → 3.52 GiB，约 36 MiB/min）。
3. **关 CUDA graphs 无效**：设置 `GGML_CUDA_DISABLE_GRAPHS=1` 后 6 分钟仍增长约 260 MiB。
4. **交互层稳定**：同一时段交互进程峰值 0.63–0.95 GiB，无持续增长；增长全部来自服务端。
5. **类别判定**：与上游已知的“每次请求/每 token 的 host 内存增长”问题一致
   （如 llama.cpp issue [#25740](https://github.com/ggml-org/llama.cpp/issues/25740)、
   ollama issue [#18106](https://github.com/ollama/ollama/issues/18106)），属于**运行器版本/实现层问题**，
   不是本仓库交互状态机或模型加载路径的问题。

**影响**：阶段 7 的 3.906 GiB 是短时基线（前几分钟）；在“30 分钟持续对话”的真实负载下，本运行器版本无法守住 4 GiB。
要满足硬上限，需要换/修运行器版本，或接受“运行一段时间后重启服务端”（后者会中断交互，不能作为连续运行验收通过手段）。

## 四、下一轮改善建议（按优先级）

1. **运行器层**：升级/固定到修复了 per-request host 内存增长的 llama.cpp 提交（或回退到无泄漏版本），
   重新构建后重跑 30 分钟检查；这是唯一能同时满足功能连续与 4 GiB 上限的路径。
2. **给内存留余量（与 1 并用）**：OCR 改为按需惰性加载（当前常驻约 300 MiB，可降到需要时再载入）；
   必要时 `--ctx-size 1024`、图像边长下调。
3. **不建议**用“定时重启 llama-server”来通过验收：会造成可见交互中断，只能作为演示兜底。
4. **2 小时电池/散热联合**：需整机与主控组织，本轮未执行。
5. **真人三主线**：目标板仍无麦克风/扬声器（`/proc/asound/cards` 仅 HDMI 输出与 APE 采集），
   需接硬件后按阶段 7 的三条主线做现场短测。

## 五、本轮实测的附带观察

- 无声卡环境下 `AudioSink` 打开失败（`Invalid sample rate [PaErrorCode -9997]`），直接暴露了“回放+null 输出”
  才能验证的上限；soak 已支持 `--sink auto|alsa|null` 并如实标注不代表真实扬声器出声。
- 首声在 30 分钟混合负载下 p50 1071–1396 ms（阶段 7 短测单轮为 713 ms）；
  主要受服务端长会话/长提示与并发影响，属于同一内存/会话增长问题的伴生现象。
- `tools/soak_test.py` 的对比/容量拒绝分类、首声统计口径（只取每个回答首短语）已修正，证据可直接复核。
