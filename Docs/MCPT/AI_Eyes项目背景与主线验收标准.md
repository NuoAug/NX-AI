## 一、项目定位

AI_Eyes 是面向**视障人群的可穿戴辅助设备**，由行走感知与空间主控、语音与视觉交互、人体参数等部分组成。本工程负责其中的**离线语音与视觉交流子系统**：让用户自然聊天，对物品和环境提问，连续追问与纠正，在设备讲话时插话，并完成视野内找物、读价、读包装日期和标牌。

核心要求是**快速、准确、流畅、稳定，回答自然且信息充分，运行内存低**。用户继续使用普通盲杖；交互子系统配合主控提供辅助，不独立承担行走与危险判断。

## 二、产品形态与目标机配置

- **眼镜＋腰间随身计算盒**，电池内置在盒内；模型推理、会话、文字识别、语音识别、合成和播放控制均在随身设备本地运行。
- 电脑仅用于开发、训练、测试和观察；最终断开电脑后，核心交互仍可独立工作。
- 目标使用场景：连续佩戴约 1—2 小时；续航基准为持续行走感知与偶尔问答，至少 2 小时并留余量。
- **计算盒已购买**。相关配置与器件如下，已购/已有器件不等于整机功能或性能已验收。

| 项目 | 型号或明确配置 | 交互侧使用边界 |
|---|---|---|
| 计算核心与载板 | **NVIDIA Jetson Orin NX 16GB＋隐溪 HCK-C1201** | 交互与主控共享同一计算平台 |
| CPU | **8 核 Arm Cortex-A78AE v8.2，64 位** | 系统、调度、前后处理及适合的轻量计算 |
| GPU | **NVIDIA Ampere，1024 个 CUDA 核心、32 个 Tensor Core** | 采用支持 ARM64 与相应 CUDA 环境的运行器；实际卸载结果需验证 |
| 专用 AI 加速器 | **2 个 NVDLA v2** | 仅用于模型、算子与软件栈支持的网络，不能视为所有模型可直接使用的 GPU 算力 |
| 运行内存 | **16GB LPDDR5，CPU/GPU 共享** | 没有额外一份独立 16GB 显存；交互额度按验收标准执行 |
| 存储与系统 | **256GB，Ubuntu 24.04.4 LTS 64 位** | 部署时记录实机环境；不填写未核实的软件库或硬盘型号 |

Orin NX 16GB 的厂家标称峰值为原规格**100 TOPS**、Super 规格**157 TOPS**，均为稀疏 INT8 口径；Super 的 157 TOPS 由 GPU 约 77 TOPS 与两路 DLA 合计约 80 TOPS 组成。该值不是单个模型的实际吞吐，也不是交互侧独占额度。交付时应分别说明各组件实际使用 CPU、GPU 或 DLA，不能只写“检测到 CUDA”或“使用 NPU”。[NVIDIA 规格](https://www.nvidia.com/en-us/autonomous-machines/embedded-systems/jetson-orin/)、[官方算力口径](https://developer.nvidia.com/blog/nvidia-jetpack-6-2-brings-super-mode-to-nvidia-jetson-orin-nano-and-jetson-orin-nx-models/)

## 三、基本设计原则

- **全链路离线运行**，最终功能不依赖互联网、云端或电脑代算。开发准备可联网取得资料和依赖；调试用本地连接不代表最终核心可以依赖外部服务。
- 不开发新闻及相关功能；交互侧视野内找物不扩展成自行建立商场地图或楼宇导航。
- 内部流程、模型组合、运行器、训练与优化方式由交互实现方自主选择，不限定模型品牌、参数量或旧代码结构。满足功能、质量、资源和接口要求是采用条件。
- 模型必须接住上下文、否定和纠正，保持图片与对象关系；不能用低占用、快输出、模板回答或大量拒答掩盖能力不足。优化前后应核对质量变化。
- 心理话题可倾听和提供一般知识，但不下诊断、不伪造出处。
- 视觉模型只依据画面描述，不自行推断真实距离、通行许可或导航结论；取得主控当前有效结果后，可以准确转述。旧照片不能作为当前通路依据。
- 音频采集、插话取消和主控危险事件不得被普通模型调用阻塞；普通回答取消不能关闭危险提醒入口。
- **每轮真实设备测试由用户启动**。提前说明目的、设备动作、预计时长和恢复步骤；结束后恢复约定状态，不自动连续启动下一轮录音、拍摄、播报或服务测试。

## 四、三方职责分工

| 角色 | 职责 |
|---|---|
| 主控侧 | RGB/深度/IMU 采集与标定、感知模型、深度姿态融合、定位与选路、空间检查、行走引导与危险判断、整机资源预算及联合验收；向交互提供图像、有效事实和事件，审查接口及交付结果 |
| 交互侧（本工程） | 音频采集与回声处理、唤醒、流式 ASR、会话与图片/对象管理、聊天/VQA/OCR、回答生成、TTS、唯一声音播放器、插话与取消、主控接口适配；自主模型选型、优化、必要训练、部署和子系统验证 |
| 体型侧 | 人体尺寸估计、实测校准与误差说明，向主控提供带单位和有效状态的人体参数；不决定是否可通行 |

## 五、职位与核心任务

**职位**：语音与视觉交互子系统负责人，全权负责本子系统的实现与交付；AI 助手在本工程内执行研发。整机主控提供需求、硬件信息、接口、资源约束和审查，具体内部设计与实现由交互侧负责。

**核心任务**：

1. **语音入口**：音频采集、回声处理、关键词唤醒、VAD、流式语音识别；本轮先唤醒“小冰”，等本地预制“我在”实际播完再提问，只唤醒不触发回答；播完立即提问不丢首字为待验收要求，不要求唤醒词与问题一口气连说，会话内支持自然停顿、补充和纠正。
2. **交流能力**：自然多轮聊天、视觉多轮问答、OCR 读字，维护图片、对象、关键文字、用户纠正及其来源；不确定时准确澄清。
3. **语音输出**：回答生成、TTS、分段连续播放、真人插话与取消；追踪实际播放状态，防止旧回答或晚到音频复播。
4. **主控适配**：遵守 `interaction.v0.1`，接入取图、场景查询、控制意图、目标观测、危险事件、取消与播放状态；复查时间、有效期和服务实例，主控不可用时如实返回状态。正式字段见仓库 `Docs/MCPT/主控与交互接口合同.md`。
5. **全流程责任**：自主选择模型与实现方式，完成环境、资产、优化、测试、必要训练、部署和交付。提交可运行系统、固定版本、复现方法与真实结果；质量、完整资源和响应共同验证。预算、功能范围或正式接口需改变时，向主控提交具体差距和变更依据。

## 六、项目主线

在 Orin NX 16GB 随身计算盒上，实现**能够自然交流、按需看图、连续追问、允许真人插话的完整离线 AI 伙伴**。软件独立于开发电脑运行，并通过主控接口取得图像与有效空间事实，与持续行走感知和危险提醒共同工作。

内部流程、模型组合、运行器和代码结构由交互侧自主设计。先形成可运行基线，依据真实质量、资源与时延决定优化或必要训练；不锁定某个模型，不以能启动、参数小或单项速度快作为合格结论。

## 七、七项核心能力（全部本地离线）

1. **中文自然聊天**：理解上下文、补充、否定和纠正，接住“为什么”“那你觉得呢”；不混淆用户与助手经历。按语境简短或详细回应，有用、自然、不机械套建议，不编造知识或出处。
2. **视觉多轮**：按需看当前画面；同图追问、翻面后“现在呢”、换物、左右纠正和两物比较均保持对应图片与对象。原图、裁剪和拍摄时间可追溯，不能把旧图改成当前图。
3. **购物与关键文字**：视野内找物，读价格、单位、优惠条件、标牌和包装日期；分清商品归属、生产日期/到期日/保质期/批次。可读时准确回答，歧义时澄清，不猜数字，也不能一律拒答。
4. **流式体验**：本轮语音入口固定先唤醒“小冰”，播放离线预制“我在”，实际播完后再接受问题；只唤醒不提交模型，确认结束后立即提问不丢首字，不要求唤醒词和问题一口气连说；说话期间处理音频，完整首段意思形成后出声、后续继续生成。会话内不逐轮重启声卡和必用模型，不因自然停顿提前执行被否定的意图。
5. **真人插话**：设备讲话时仍可接收有效用户输入，及时停声、清队列和取消旧任务；新话语完整处理，旧文本/音频/回调不复活。区分真人、设备回声和背景声音，分别检查误打断与漏打断。
6. **主控协作**：图片和空间事实按 `interaction.v0.1` 取得；距离、通行、绕行只读有效主控结果。最终控制意图提交主控处理，危险事件及时抢占；读取、入队和播放相关片段前复查事实有效期。
7. **失效处理**：看不清、听不全、事实过期、模型超时或设备失效时明确反馈，保持状态可判断、可恢复；重连/重启后不沿用旧动作、旧空间结果或错误对象关系。

## 八、验收标准

1. **内存**：完整交互子系统正常占用目标为 **1.5—2 GiB**，首轮目标板峰值接入上限为 **≤4 GiB（4×1024³ 字节）**。统计包括所有模型、CPU/GPU 相关分配、运行器、子进程、上下文、图片/音频缓存及临时工作区，覆盖冷加载、首次请求、任务切换和取消立即重试。共享部分不重复计算，不依赖持续 swap/zram 降低驻留数字。峰值超限不能按当前预算验收；峰值达标但正常占用超过目标，须明确报告并继续优化。

2. **响应时延**：回答计时从**用户实际说完**开始，到**第一段有实质回答内容的声音实际发出**为止，包含端点、识别、取图/推理、合成和播放等待。普通热态聊天优先验证有效首声 ≤1 秒并继续缩短，同时报告 P95，普通单图及同图追问 P95 争取 ≤3 秒；OCR 按清晰可读、需调整/重拍分别记录，不与普通单图混算或隐藏重拍等待。唤醒词结束到实际确认首声 P95 争取 ≤0.5 秒；真人插话开始到旧声音实际停止 P95 争取 ≤0.3 秒。以上为工程初筛目标，冷/热、聊天/新图/同图/OCR 分别报告样本数和实际结果；首 token、等待词和 HTTP 返回不算有效首声，少量小样不外推长期 P95。

3. **三条链路真人实测与能力质量**：自然多轮聊天；包装翻面读日期并继续追问；两商品价格/文字比较。每条须包含连续追问、补充或纠正，并用不同表达、物品或画面验证，不能只靠固定台词和固定布局。逐类记录成功、失败、澄清、重拍与拒答；检查话题/角色、图片/对象、价格单位和日期字段。关键数字编造、错误确定商品归属、越权空间判断或旧回答复播不能用综合平均分抵消。模型自评分、流利长篇和大量拒答不能单独作为质量合格依据。

4. **异常处理与主控并行**：真人插话、紧急抢占、无画面、模型超时、主控失联/重启、音频设备失效均须正确反馈、停止无效输出并合理恢复，不只要求进程不崩溃。分别核对实际停声、待播清理、后台计算退出和晚到结果；新请求不导致旧重任务无界堆积。与真实主控同时运行时，交互不得阻塞感知、空间更新或危险提醒；主控未接入时明确“联合未测”，替身不算真实联调。

5. **持续运行与续航**：代表性短测通过后完成至少 **30 分钟持续检查**，覆盖聊天、换图、读字、插话与取消重试，记录内存增长、错误、恢复、温升和实际响应。再由主控组织**至少 2 小时整机电池续航与腰间散热联合验收**，负载为持续行走感知与偶尔问答，说明问答占比；不以市电运行替代电池续航，也不外推为 2 小时不停聊天。

6. **验收口径与交付**：最终核心能力须在目标计算盒断开开发电脑、无互联网依赖的条件下工作，并由真人确认实际交流和声音。软件回归、电脑文件评测、目标板运行、真人体验及整机联合分别给出结论，单项通过不能代替其他层级。提交代码/模型/运行器版本、配置、实际 CPU/GPU/DLA 后端、输入与复现步骤、原始结果、未测/未过项和恢复方式。真实设备测试每轮由用户启动；缺少现场条件时继续独立软件工作，不能伪造验收通过。
