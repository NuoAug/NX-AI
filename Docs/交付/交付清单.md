关键数字汇总（详见各阶段报告）：全量回归 **354 passed / 285.19 s**（0 failed）；短时整栈内存峰值 **3.906 GiB ≤ 4 GiB**；热聊首声 **713 ms**（探针 911 ms）；插话停声 **6 ms**；OCR 640×480 p95 **357 ms**；双图价格比较 **740–771 ms**；声纹同人 0.9799 / 异人 0.3307。

> **口径说明（2026-11-16 审查补充，数字本身不改）**
> - **回归数不可跨版本比较**：`354 passed` 属更早版本（阶段 5–7 时期，测试集合更小）。此后本机又执行过多轮全量：`907`（acceptance5）、`950`（acceptance7），两者都只覆盖 `Testbench/Tests` 一个集合；根 `Tests/` 是另一个集合（`6 failed / 321 passed / 44 skipped`，六条失败与代码改动无关：3 条声纹 identity、缺 OCR `PP-OCRv6_det_small.onnx`、无 `/dev/video*`、llama 服务 8080 未起）。**这几个数只能并列，不能相加、不能互换**；唯一可比的是「同一集合、`failed=0`、skipped 集合不变」。
> - **内存 `within_cap` 是旧口径**：阶段 7/8 的 `within_cap: true` 来自「三进程 RSS 简单相加」，既不含共享页去重，也不含 NvMap、SwapPss，只能当筛查量。现行口径（`Testbench/metrics.py`、`NX-AI/Tools/mem_probe.py`）已改为「保守上界和 / 去重估计 / 不可判定」三态，只有 `provably_within_cap` 才算通过；`SwapPss`、NvMap 读不到时判 `undeterminable`，不得按 0 计。
> - **「首声」是软件播放提交时刻**：引擎在 `sink.play()` 返回后立即取时，不含声学出声延迟；`acoustic_first_audio_ms` 本机始终「未测量」。
阶段 8 持续运行（2026-11-12）：两次 30 分钟均为 **0 硬失败**（35/34 与 30/30 回答，容量拒绝 8/6 属正常上限），但整栈内存峰值 **4.999 / 5.61 GiB**（llama-server 持续增长 ~35–45 MiB/min，文本-only 同样增长），**超出 4 GiB 硬上限，内存项未通过**。
